# LicenseRecover v1.2.39

本版修复 .NET 授权已经能够正常执行 `gencode -> DoRegistry -> CheckReInfo`、甚至创建本地授权数据库，但应用仍提示“系统不支持任何模式”的最后一层问题。

## 根因

v1.2.38 的 ASP.NET Hosted AppDomain 与大小写注册链已经能够正常运行，但 `RegStr` 仍可能由旧本地授权或 `ITMC.Web.dll` 的兼容模式列表决定；当前站点自己的 `SoftVersionID` 若恰好不在其中，就会出现授权写入成功但业务层模式判断不命中的情况。

## 修复

- 当前目标站点 `config.xml`（站点根优先、bin 兼容）的 `SystemSoft/SoftVersionID` 固定作为 .NET `RegStr` 的首个主模式。
- 只有该值与当前目标目录检测到的 `Detection.versionId` 一致且格式合法时才采用；不会从目录名或默认产品表猜测。
- 已存在的有效本地授权 `RegStr` 与目标 `ITMC.Web.dll` 中证明的同族产品项作为兼容模式追加并去重。
- GUI 一键恢复和 CLI `gencode` 统一调用同一个 `detectDotNetRegStr()`。
- 调用目标注册组件前增加硬性门禁：检测到 `SoftVersionID` 时，最终 `RegStr` 必须明确包含它，否则以 `[MODE]` 失败并停止写入。

## 回归验证

新增 YX030308 风格夹具：`ITMC.Web.dll` 只暴露 `YX030301` 与 `YX030321` 两个兼容模式，故意不暴露当前 `YX030308`；最终 RegStr 必须为 `YX030308,YX030301,YX030321`。

## 保持不变

- v1.2.37/v1.2.38 的真实 ASP.NET Hosted AppDomain 与站点根路径绑定不变；
- 小写 `itmcRegedit.dll` 优先、大写 `ITMC.Regedit.dll` 回退规则不变；
- `registrationProduct` 与应用 `ProName`/`RegStr` 继续分离；
- PRE-BLOCK FIRST、备份、失败回滚和默认授权联网隔离不变；
- 不修改目标注册 DLL，也不改变目标组件自己的申请号、`DoRegistry()`、`CheckReInfo()` 算法。
