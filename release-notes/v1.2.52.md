# LicenseRecover v1.2.52

本版修复 DS2406 在真实 `DS24` 父产品配置结构下的识别与诊断假阳性。

## 根因

真实 DS2406 部署不是把 `data/config.xml/SystemSoft/SoftVersionID` 写成 `DS2406`，而是：

- 父产品：`SoftVersionID=DS24`；
- 子模式：通过 `<System id="DS2401"> ... <System id="DS2406">` 枚举；
- 当前实例：根 `systemConfig.yml` 的 `global.system.VersionID=DS2406`。

旧逻辑虽然能从目标二进制证明运行产品 `DS24`，但在没有静态 `regInfo` 时仍把任务标为 READY，并计划在执行阶段调用目标 `RegisterMain.getRegInfo()` 获取 RegStr。现有本地授权缺失或不可读时，probe 调用本身成功但 `TARGET_REGSTR` 为空，于是后续才失败。

## 修复

- 新增 DS24 父产品 / 具体模式诊断证据：
  - `systemConfig.yml` 当前 VersionID 必须与检测到的具体模式一致；
  - `data/config.xml` 必须声明父产品 `DS24` 并实际枚举当前 `<System id>`；
  - 目标 `IXmlUtil.class` 必须证明 `global.system.VersionID -> IStatic._SYS_CODE`；
  - 目标 `SystemSetListener.class` 必须证明启动时使用 `RegStr.contains(IStatic._SYS_CODE)`；
  - 目标运行产品必须已由目标目录证明为 `DS24`。
- 该链只证明“当前模式属于 DS24 且启动门消费该模式”，不会把模式 ID 合成为新的 RegStr。
- 当上述模式证据存在、但没有从目标配置或现有本地授权获得真实 RegStr 时，计划直接显示 BLOCKED，并说明“已证明 DS24 子模式 DS2406，但未发现现有 RegStr”。
- Java target-native probe 现在分别输出调用状态与证据状态；RegStr 为空时为 `PROBE_EVIDENCE=EMPTY/PRODUCT_ONLY`、`RESULT: NO_REGSTR`。

## 验证

- 使用真实 DS2406 恢复后的 `IXmlUtil.class`、`IGlobal.class`、`SystemSetListener.class` 做本地证据测试。
- 正向：DS24 + 枚举 DS2406 + 当前 VersionID=DS2406 + 完整启动消费链可确认当前模式。
- 反向：当前 VersionID 不匹配、运行产品不匹配、配置未枚举 DS2406 时均 fail-closed。
- 新增正式 smoke test 与 CI 源码防回退规则。
