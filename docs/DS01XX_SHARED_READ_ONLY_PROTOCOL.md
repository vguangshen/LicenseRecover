# DS0101 / DS0105 共用只读授权判据的依据

审核日期：2026-11-03。用户确认此前第二项名称为 DS0105。以下只读比较使用仓库外的新鲜 DS0101、DS0105 代码/配置副本，以及已按当前组件哈希静态恢复的 CIL。没有访问真实安装目录、加载目标程序集、执行原生验证、修改输入或执行 Patch。真实配置、授权载荷、机器标识、厂商二进制和完整反汇编不提交。

## 一个协议，两组已审构建

当前两项均由大写 `ITMC.Regedit` 的 JSON 本地授权协议完成已审正向判断：DES/CBC 载荷中包含 `RegeditInfo`，再核对本机身份、期限、无限计次和当前产品范围。应用名称只用于报告；`SoftVersionID` 取所选站点根配置，本地密码产品参数取已审核网站入口的 `ProName`。

两项整体程序集不同，但以下 30 个已解析引用的关键方法 CIL 正文完全相同，不需要放宽为“名字相似”或忽略分支才能匹配：

- `RegeditMain.CheckReInfo`、`CheckLocalReg`、`getLocalRegInfo`、`getRegNo`；

- `XMLFiles` 的配置读取方法及上述集合中实际存在的相关实现。

两项使用的 Newtonsoft.Json、LiteDB 和日志依赖也逐字节相同。密码依赖 DLL 整体不同，仍保留各自已经审核过的绑定，不能仅凭类型名把它们视为任意可替换实现。

当前新副本的两份根配置与前轮副本均逐字节相同，均为本地优先模式、有本地载荷且没有非空机器覆盖号。没有因新反馈虚构新记录、改变配置或选择某个更容易通过的机器号。

## 网站差异为何不要求另一套本地算法

两个网站的 `CheckReg`、`GetProVersion` 等方法并不完全相同。DS0101 从产品关系集合筛选兼容项，DS0105 向关系查询直接传入当前模式；二者随后都把本产品 `ProName` 与当前 `SoftVersionID` 补入候选集合。本产品、本机、期限、计次和当前模式均通过时，可以复用同一个独立正向谓词，无须给 DS0105 再写一套授权算法。

但是，关系数据库、父产品顺序、网站缓存和异常路径存在各自的入口语义。识别为同一注册协议，不等于所有网站入口、产品关系或后备机制都可以互换。

## 面向后续同系列版本的复用边界

协议族识别与授权证明应分开：类型、签名、载荷结构和语义特征可用来识别同族候选；当前授权接受仍需相应入口、关键方法及依赖的审核证据。一个新 DLL 只改变业务代码时，不应该要求再写一套本地算法，但也不能仅因文件名、版本前缀或几个方法同名就自动升绿。

方法语义指纹可以减少对整体 DLL 哈希的依赖，但必须覆盖引用解析、字段/局部类型、异常处理、构造器和静态初始化，以及参与判定的传递依赖。这里的文本比较只是已有审核的佐证，不是已经实现的通用 IL 等价证明；保护器和模块初始化存在变化，不能据 30 个方法正文相同便接受任意新组件。

既有 `LegacyDotNetProtocol` 的 DS01xx“旧协议”分类描述注册页/写回兼容路径，其中申请号与授权码采用固定字段格式。它不能直接作为本只读扫描的载荷分组：相同 DS01xx 安装同时有大写 JSON 本地路径与小写旧格式后备。只读引擎应按实际注册组件的协议选择公共算法，把产品与版本作为参数，避免用目录名或 DS 前缀强行路由。

后续回归应覆盖同协议不同产品/模式、目录重命名、未知同族变体、损坏或混用组件，以及未审核依赖；未知变体可以报告“已识别同族、授权逻辑待审”，但不能伪装为已经通过原生验证或可信 Patch 比对。
