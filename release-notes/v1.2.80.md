# LicenseRecover v1.2.80

## Correct the actual .NET RegeditInfo.UserID, not just WebSerUserID

v1.2.79 set the .NET helper's RegeditMain.UserID to fwq, but static examination of the target uppercase vendor DLL showed this setter updates WebSerUserID and does **not** set the UserID embedded in the encrypted RegeditInfo record. Relevant protected website pages read RegeditInfo.UserID instead.

- For the exact audited uppercase ITMC.Regedit.dll (SHA-256 `222df2d024efb4b30510af9bf5f552646e4e2f75ea9b3795daa7a279d8a6f725`), after a successful native DoRegistry() call, reconcile an **absent/empty** RegeditInfo.UserID in the native encrypted `regName` record to `fwq`.
- Preserve original RegInfo product, RegStr, machine identity, dates, use limits and all other fields, plus original six-digit envelope. A matching fwq is left alone; any different nonempty identity, unrecognized field schema, missing machine ID or product/version mismatch fails closed.
- Create durable backups before any mutation in this specific path. Re-encrypt, read back, run the original registration and website verification, then re-read the final persisted record; on failure restore the original snapshots.
- Do not modify proprietary DLLs, unrelated registration values or the lowercase VM-protected registration component. Older DS01xx Legacy and other uppercase builds remain on their existing paths.

## Test coverage and evidence

- A user-supplied authorized YX030107 site-root config.xml contained a decryptable 14-field RegInfo record with UserID=null, product YX0302 and selected YX030107 in RegStr. An **offline in-memory** decode/change/encode round trip preserved the other 13 fields and the ciphertext's 752-hex-character length. No private original configuration or encrypted license data is committed.
- Updated synthetic regression tests use fabricated multi-version, 14-field RegInfo records. Verify null, empty, already-matching, nonmatching, wrong product/version, duplicate UserID and missing RegID cases.
- GitHub CI includes source compilation/distribution packaging and two hosted Windows integration suites.

**Limitations:** The real website was not executed; no claim is made that all IIS business functions now pass in the target environment. Verify the new release on a backed-up copy, ensure the application's original authorization and product checks succeed, and restart IIS/app pool to clear cached RegInfo after a successful one-click recovery.
