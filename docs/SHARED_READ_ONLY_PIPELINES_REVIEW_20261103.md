# 共享 Java/.NET 只读识别通道复审（2026-11-03）

## 范围和结论边界

本次复审检查了 AppDetector、ModernGUI 批量扫描调用链、ReadOnlyInspection、共享 Java/.NET 扫描入口、协议数据表、独立谓词、PE/CLI 元数据读取、旧版注册兼容代码以及运行时打包测试。审查只读取仓库和独立样本副本；没有读取真实安装目录、执行厂商程序集或 Java 注册类、修改注册信息、执行 Patch 或屏蔽网络。

当前实现可以采用两个对外识别入口：`LicenseRecoverReadOnlyJavaScanner` 和 `LicenseRecoverReadOnlyDotNetScanner`。内部保留按实际协议和完整构建证据选择的审核谓词。把入口统一并不意味着所有未知构建都获得了授权语义证明。

这是一份代码与局部合成测试复审记录。完整测试、最终 ZIP 运行时测试和新鲜样本 GUI/CLI 对照结果应以本轮主验证报告为准，不能从本记录推出全部应用已验证有效。

## 共同识别和授权证明

| 观测 | 可以得出的结果 | 不能得出的结果 |
| --- | --- | --- |
| Java/.NET 文件结构、版本、配置存在 | 应用识别和协议候选 | 激活、Patch 或未激活 |
| 未知程序集的本地 TypeDef、方法签名及字段模型匹配 | 同系列注册接口候选 | 方法体等价、只读安全或授权通过 |
| 已审注册组件哈希相同但网站/依赖不同 | 已知协议家族，完整构建尚未审核 | 继承另一网站的有效授权结论 |
| 网站、注册组件和相关依赖完整匹配审核数据 | 允许使用对应的独立只读谓词 | 原版/Patch 来源证明 |
| 已审当前入口接受谓词通过且输入复核一致 | 当前授权检查通过，来源未细分 | 厂商签发真实性、业务功能全部可用 |
| 本地记录缺失、机器字段不匹配、格式未支持 | 局部事实及仍待核的授权来源 | 网络、硬件狗、组合注册或站点缓存全部拒绝 |
| 可核验来源的原版/Patch 双指纹完整匹配 | 单独的代码原版/Patch 结论 | 原生授权有效 |

.NET Catalog 的 UpperBinding/ExtendedBinding 是数据化审核绑定，不按目录名或版本前缀选择有效状态。DS0101 与 DS0105 的 30 个关键可读注册方法 CIL 相同，可以共用现代 JSON/DES 正向谓词；两网站入口及保护器仍有差异，因此继续分别绑定其网站和依赖证据。详见 `DS01XX_SHARED_READ_ONLY_PROTOCOL.md`。

Java 共享扫描入口按静态门槛、本地谓词和实际启动入口收集证据；完整 class/JAR/启动资源匹配仍是授权推断的条件。共享 anchor 只筛选候选，不能采用首次命中就复用另一完整构建的规则。

## 本轮发现及修复复核

1. **PE TypeSpec 指数展开。** 原接口候选解析器只有递归深度、单 blob 和行数限制。多层小 TypeSpec 重复引用可在深度限制内制造指数级字符串和计算量。已加入模块级节点/工作量/累计文本预算、生成字符串长度限制、活动 TypeSpec 循环检测、带逻辑深度成本的缓存，并约束 locals 引用合并。复审检查了缓存命中、拼接、Base64 原始签名键和堆字符串路径，未见原扩张路径残留。
2. **变化后仍输出旧审核标志。** 原统一 .NET 扫描在撤销状态后仍保留首次 protocol Assessment，使 JSON 的 `protocolBindingAudited` 和“当前入口与依赖”描述可能过期。已改为变化或检查错误时清空当前协议证明；不能把旧绑定当作当前证据。
3. **非正向结果的配置复核不足。** 原现代 .NET 验证器在本地记录缺失或机器字段不匹配时提前返回，只对正向结果复核根配置。已取消该提前返回，所有结果都复核配置和代码绑定后重算；统一 Catalog 快照也包含根 `config.xml`，变化撤销局部事实及协议证明。
4. **Java 同 anchor 变体与时钟边界。** 本轮实现先比较每个候选的完整代码/资源集合并拒绝审核记录歧义；本地和备用入口在最终输入复核后使用当前时间重算。复审确认当前正向路径使用最终时钟，而不是长时间依赖读取前的旧到期判断。
5. **分发测试接线。** 全量主源码与内部类通过编译产物清单进入 Runtime JAR，分发测试校验字节哈希并确认类来自最终 Runtime JAR。新增共享扫描入口测试也必须在源码验证和两个解压 ZIP 的行为测试列表中执行；不能只把新类打包而不运行新路径。
6. **识别前置的无界读取。** AppDetector 与 AutoRecovery 在进入 Scanner 前读取版本配置和程序集候选元数据，原先存在 `readAllBytes`/`readAllLines` 无界分配。现以共享有限读取器限制配置 4 MiB、启动属性 1 MiB、程序集元数据 64 MiB、兼容数据库 16 MiB；按已知有限长度只分配一次 byte[]，流中缩短或增长会撤销读取，避免 ByteArrayOutputStream 的扩容与复制峰值。程序集字符串提取另限单段 16 Ki 字符、累计 8 Mi 字符及 100000 个候选；超过预算整次候选失效，不保留有利的前缀产品标识。既有 data/classes/bin 回退顺序仍保留。
7. **协议快照的内存峰值。** Catalog 对所有角色使用流式 SHA-256，192 MiB 集合上限在读取前核对，避免先分配再拒绝。未知注册元数据逐个以 16 MiB 上限精确读取，并核对首次观测的摘要；不同时保留两份程序集原始字节。基本 PE 观察保留 128 MiB 限额但改为单次分配，不能据此声称 128 MiB 输入可在小堆中解析。

## 副作用和旧版兼容边界

GUI 只读批量链为 `AppDetector.detectLocal` → 只读计划/静态恢复元数据检测 → `ReadOnlyInspection` → 两个共享 Scanner。审查范围内没有发现这条链调用 recover、doRegistry、Patch、配置回写或网络阻断。固定系统 PowerShell/WMIC 仅用于独立本机身份、命令环境及注册表只读查询，不加载目标注册代码；其不可用会保留不确定性。

`LegacyDotNetProtocol` 和 AutoRecovery 的 DS01xx 注册页兼容分类仍服务于既有恢复流程。离线交换码/注册页写回格式与运行时大写 JSON 本地检查可以并存。不得用旧版分类或注释决定只读授权状态，也不能把恢复能力候选当作授权证明。

前置预算修复不改变授权判据：缺少或超限的候选元数据不会升级为授权通过。GUI 超时也不应被当作内存或计算预算；各读取和解析入口仍需独立限额。JavaPlan 的配置、属性、class 与 JAR 条目读取也纳入相同预算规则，并有独立边界回归。

CLI 接口解析仍有明确能力边界：部分合法 FieldPtr/MethodPtr 间接表、扩展表及签名形式尚不支持，会报告扫描检查失败，不会转成授权无效或授权通过。API 识别允许普通 Unicode 程序集名，并不由显示名称建立授权信任。

## 本复审实际运行的测试

在独立审查输出目录用本机 Java 8 编译 `LicenseRecoverReadOnlyPeMetadata.java` 和对应合成测试，并以 `-Xmx64m` 运行：**78 项检查通过**。测试包含 PE32/PE32+、正确与错误方法归属、本地与外部同名类型、损坏元数据、TypeSpec DAG 展开、自环/互环、缓存深度绕限、累计文本预算和总节点预算。只使用合成 PE 数据，没有厂商二进制或真实注册码进入测试夹具。

随后补充普通 Unicode 程序集名及精确文件读取边界，最终 PE 测试增至 **85 项**，源码和两份最终 ZIP 运行时均通过。.NET 共享 Scanner 测试 **17 项**通过，其中独立 `-Xmx48m` 子进程验证 96 MiB 组件的流式哈希、193 MiB 集合的读取前拒绝，以及未知注册元数据限额。JavaPlan 另测 4 MiB 配置、16 MiB class/JAR 条目的精确及超限边界、压缩大条目、条目长度不符、早期 token 撤销、回退和禁止执行目标代码。

另在独立输出目录用 Java 8 编译当前全部主源码与 `LicenseRecoverMetadataReadBudgetTest`，以 `-Xmx64m` 运行：**16 项检查通过**。覆盖正常 Java/.NET 元数据识别、超限启动属性/data/root 配置及既有回退、文件后部损坏的 UTF-8 不能被有利的属性前缀掩盖、超限程序集与兼容数据库、短文件大字符串扩张、拒绝部分有利产品证据、读取预算边界，以及目标夹具字节不变。该测试已经列入本轮源码与完整/更新 ZIP 的测试接线，最终每包执行结果仍以主验证报告为准。

这些检查证明所测元数据解析与资源边界行为，不证明任何真实应用授权成功，也不代替本轮完整打包与真实副本扫描验证。
