# LicenseRecover v1.2.71

本轮开发针对 .NET 局部记录与实际站点授权不一致的反馈，补充来源和扫描环境说明。入口条件通过显示蓝色（来源未确认）；深绿代表原生有效、浅绿代表确认 Patch、白色代表原生无效，灰色为未验证、红色为检测错误，入口拒绝单独用琥珀色。

- 对外只保留 Java、.NET 两个共享只读检测入口。按真实协议与已审组件/参数复用内部判据，不按目录名或产品前缀推定授权。
- 集中 .NET 协议家族与构建证据；未知程序集通过实际 CLI 类型归属、方法签名和字段模型识别同族候选，但候选不直接升绿。DS0101、DS0105 使用同一个现代 JSON/DES 本地谓词。
- 修正 Java 同入口多构建的完整指纹选择和复读跨到期时间的判定；组件或配置变化时撤销旧本地事实与协议审核标志。限制元数据签名展开和扫描前输入的资源用量。

- 增加 YunClient 组合注册来源的只读观察，明确区分机器覆盖号、候选本地载荷和真正授权接受。注册表存在不直接升绿，不调用会写文件的原生导入方法，也不读取 CRM 密码。
- 补充已审核大写注册组件的 WMIC 覆盖机器号规则。可信可执行路径、AutoRun、字节编码和输出解析均须满足审核范围，无法证明时保留未知；不以普通 WMI 成功代替 WMIC 协议。
- 本地机器不符的文字明确限定为“本地记录标识未匹配（站点待核）”；未支持分支显示“本地验证未覆盖（其他方式待核）”，并解释其他注册组件、组合来源及运行缓存边界。
- 检测异常的具体原因放入可见原因列。

用户已澄清第二项软件为 DS0105。新鲜 DS0101、DS0105 副本由同一现代协议检查通过；YX0102 本地记录与扫描环境标识未匹配，这只描述本地路径，不能据此判断整个站点未激活。

小写 VM、联网/硬件狗、组合产品映射及 IIS 进程缓存尚未全部闭合。此次没有宣称所有协议已支持，也没有把用户反馈或配置存在替代实际验证证据。真实软件、注册表和授权记录未被修改。
