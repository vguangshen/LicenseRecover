# LicenseRecover v1.2.10

本版本根据用户提供的 QT40101 真实生产包，完成该平台 RegStr 的最后一层运行时确认。

## QT40101

真实字节码显示：

- `SystemInfo.registerId` 从 `config1.xml` 读取为 `QT401`，因此 RegisterMain 运行产品号仍为 `QT401`；
- 当前具体应用由 `systemConfig.yml` / `config.xml` 确认为 `QT40101`；
- `RegisterListener.run()` 在读取 `getRegInfo().getRegStr()` 之前已经将 `RegisterContant.hasRegister=true` 与 `authorizeFlag=true`；
- 后续 ClassPid 遍历只可能再次把 `authorizeFlag` 设为 true，不存在把它改回 false 的路径；
- `RegisterInterceptor` 的访问门槛仅检查 `hasRegister / authorizeFlag / hasInitDatabase`。

因此该真实版本的启动授权并不要求 RegStr 命中特定 ClassPid。v1.2.10 对 **QT40101 这一精确产品** 使用具体 VersionID `QT40101` 作为确定性的最小非空 RegStr。

扫描后预期显示：

- 类型/授权代际：`Java / QT401 / classes-config`
- SoftVersionID：`QT40101`
- 授权族：`QT401`
- 运行校验ID：`QT401`
- RegStr：`QT40101`
- 状态：`待处理`

## 优先级与安全边界

若应用中已经存在 `regType=1 + regName` 的旧本地授权，仍优先使用 v1.2.9 的只读动态恢复结果。只有无法恢复旧 RegStr 时才使用上述 QT40101 精确规则。其它 QT401xx 或未知 classes-config 产品不会自动套用此值。
