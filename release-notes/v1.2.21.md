# LicenseRecover v1.2.21

本版把 Java / .NET 一键恢复统一改为 **PRE-BLOCK FIRST**：在调用目标软件自己的任何注册代码前先建立授权网络隔离，避免第一次 Patch 的 `gencode / DoRegistry / CheckReInfo / RegisterMain.getRegInfo()` 阶段仍有机会向原授权云端发送请求。

- **.NET 先隔离再注册**：在首次调用 `LicenseRecover.NET.exe gencode` 前，先为该 helper EXE 安装临时 Windows Firewall 出站阻断规则，并提前把目标 `config.xml / Web.config / *.dll.config / *.exe.config` 中已识别的授权 Service/URL 指向 `127.0.0.1:9`。随后才执行 `gencode -> RegeditMain.DoRegistry -> RegeditMain.CheckReInfo`。
- **.NET 硬编码 URL 也受保护**：临时防火墙规则按 `LicenseRecover.NET.exe` 程序路径绑定，因此目标 `ITMC.Regedit.dll` 即使内部存在硬编码授权地址，也运行在被阻断的 helper 进程里。helper 子进程同时设置 `HTTP_PROXY / HTTPS_PROXY / ALL_PROXY = http://127.0.0.1:9` 作为第二层防护。
- **Fail-closed**：如果无法建立临时 Windows Firewall 阻断，工具拒绝调用厂商注册代码，不会退回“先注册后屏蔽”。操作结束后无论成功失败都会尝试删除临时规则。
- **Java 子进程先隔离**：在任何目标 `RegisterMain.getRegInfo()/checkReInfo()` 调用前，LicenseRecover 专用子 JVM 会把 Java HTTP/HTTPS 代理指向 `127.0.0.1:9` 并设置短连接超时；随后写入本地授权时仍把授权 Service 改为本地 inert endpoint。没有对系统 `java.exe` 添加全局防火墙规则，以免误伤同机 Tomcat 或其他 Java 服务。
- **回滚语义保持完整**：.NET 在 pre-block 前快照注册与网络配置；`gencode / DoRegistry / CheckReInfo` 任一步失败都恢复原文件。成功且保持“阻断授权联网”时继续保留配置阻断；若显式使用 `--no-block-net`，则只恢复原网络 Service/sidecar 配置，不撤销已经通过原生校验的本地注册。
- **保留 v1.2.20 的目录证据规则**：YX0102 继续按真实目标目录解析为 `ProName=YS01 / RegStr=YX0102`；YX030506 继续使用目标 `PRODUCT_ALL_NUM -> RegisterMain` 数据流确认运行 ID。没有恢复任何默认 ProductID / RegStr 兜底。

> 为了把“第一次 Patch 无云端出站”的保证扩展到目标站点本身，建议 Patch 前停止对应 IIS App Pool / Tomcat。v1.2.21 的临时隔离针对 LicenseRecover 调用的厂商注册代码；已经在运行的独立 IIS/Tomcat 进程不属于该 helper/子 JVM。
