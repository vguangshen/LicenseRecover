# LicenseRecover v1.2.54

本版把 DS2406 “未初始化本地授权”状态从纯阻止改为目标原生 **request-only** 流程。

## 实际验证

使用完整 DS2406 目录和真实 `WEB-INF/lib/ITMCReg-1.0.2.jar` 本地执行：

```
new RegisterMain("DS24", root).newRegistry()
```

在根 `config.xml` 不存在的情况下成功返回申请号。调用前后再次检查根 `config.xml`，文件均不存在，因此 `newRegistry()` 本身不会初始化或写入本地授权。

## Changed

- DS24 / DS2406 干净安装满足完整目标证据时新增 `nativeRequestReady`。
- Java target-native host 新增 `request` 模式，只反射调用目标 `RegisterMain.newRegistry()`。
- 一键流程在 `automaticRecoveryReady=false && nativeRequestReady=true` 时：
  1. 使用已证明的目标构造器 ABI；
  2. 调用目标 `newRegistry()`；
  3. 返回申请号；
  4. 立即停止。
- 该路径不会要求 RegStr，不会生成离线注册码，不会调用 `doRegistry()`，不会写授权配置。
- GUI 单独显示 request-only 完成状态和申请号，不再显示“RegisterMain.checkReInfo() 通过”。
- 批量执行对 request-only 使用非写入状态，不把它算作完整授权恢复。

## Safety / fail-closed

- `DS2406` 模式 ID 仍不会被合成为现有 RegStr。
- 根 `config.xml` 已存在但 RegStr 不可读时，不启用 request-only；继续保持阻止并提示现有授权可能不完整。
- request-only 必须同时具备 DS24/DS2406 目录证据、目标注册 JAR、运行产品和目标构造器 profile。
- 没有合法注册码时不会进入授权写回。
