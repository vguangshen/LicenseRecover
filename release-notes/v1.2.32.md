# LicenseRecover v1.2.32

本版根据真实 Windows / .NET Framework 上 YX030101 的 v1.2.31 回归继续修复小写 `itmcRegedit.dll` 注册链。

## 根因

v1.2.31 已成功创建 ASP.NET `HttpContext`，但随后反射调用原 `LicenseRecover.NET.exe` EntryPoint。原 helper 的 `Program.Run()` 在检测到小写 `itmcRegedit.dll` 时会创建子 AppDomain，并用 `Assembly.GetEntryAssembly().Location` 去 `CreateInstanceFromAndUnwrap(..., "LicenseRecoverNet.DomainRunner")`。在 host 场景下 EntryAssembly 是 `LicenseRecover.NET.AspNetHost.exe`，不是 `LicenseRecover.NET.exe`，因此真实机报“未能从程序集 LicenseRecover.NET.AspNetHost 中加载类型 LicenseRecoverNet.DomainRunner”。

仅修正程序集名也不够，因为子 AppDomain 不会继承父域的 `HttpContext.Current`，目标注册组件仍会失去其 `Server.MapPath` 上下文。

## 修复

- ASP.NET host 继续加载原始、未修改的 `LicenseRecover.NET.exe`。
- host 反射调用 helper 自己的 `ParseArgs()`，保留原命令行解析语义。
- 随后直接调用 helper 的公开 `RunDirect()`，在同一个 ASP.NET AppDomain 内执行目标注册流程，不再进入 `RunInBinDomain()`。
- `HttpContext.Current` 因此在 `gencode -> doreg -> verify` 期间保持有效；目标 `itmcRegedit.dll` 仍负责动态申请号、离线授权码写入与原生校验。
- 大写 `ITMC.Regedit.dll` / `LicenseRecover.NET.Modern.exe` 路线不变。

## 验证重点

YX030101 日志应出现 `[ASPNET_HOST] helperDispatch=RunDirect/same-AppDomain`，并且不再出现 `LicenseRecoverNet.DomainRunner` 子域加载错误。
