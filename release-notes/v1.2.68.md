# LicenseRecover v1.2.68

本版发布真实样本审计、可追溯的只读扫描证据与运行时打包改进。**尚未实现这 26 个真实应用的原生授权有效/无效或 Patch 确认。**

## 本次改进

- 批量扫描和被动预览使用明确的静态 Java 识别入口，修复旧计划在部分配置下可能通过 `ExistingLocalRegStrProbe` 执行目标初始化器、构造器和 `getRegInfo()` 的问题；新增带写入哨兵与正控制的合成回归测试。
- 新增当前组件 SHA-256、Java class 运行时下限、.NET PE/CLI 元数据/Assembly 版本、检测方法、安全审计范围和具体未验证原因。元数据版本不代表当前实际服务运行时版本。
- 根据真实组件哈希关联已经发现的验证副作用，明确解释为何不调用现有原生检查。这些观察哈希不是可信原版/Patch 指纹，不会提升授权状态。
- 自动收录全部新编译主类和内部类，逐类核对 SHA-256，从最终完整 ZIP 与更新 ZIP 的真实类路径执行行为测试，防止再次出现构建通过但发行包缺类的问题。

## 本地验证结果与限制

- 16 个 Java、10 个 .NET 应用的独立扫描输入副本均可识别：识别 26，异常 0，授权未验证 26。副本包含检测输入，不声称可启动完整业务系统。
- 当前经过独立审核的真实原版/Patch 双指纹库仍为空；没有将注册码存在、RegStr 非空、历史 Patch 或网络屏蔽当作有效授权证据。
- 静态审计发现 Java/.NET 原生检查存在配置/日志写入、有限计次更新与网络/HASP 回退。批准后的 Java 副本受限调用在依赖初始化阶段中断，没有取得可用的原生布尔判定；异常不等于授权无效。
- 因此真实软件继续显示灰色“未验证”是当前证据支持的结果，不能理解为未激活或 Patch 失败。

## 下载、更新与测试

- 完整便携包：`LicenseRecover-latest.zip`，自带 Windows x64 Java 8 JRE，解压后运行 `LicenseRecoverGUI.exe`。
- 轻量更新包：`LicenseRecover-update.zip`。已有版本可以使用右下角“检查更新”，安装后确认界面版本为 **v1.2.68**。
- 使用 `SHA256SUMS.txt` 校验两份 ZIP。建议先在应用目录副本上进入批量页，仅点击“扫描子目录”，检查识别数量、具体原因与错误日志；本次扫描测试不需要执行一键恢复或方式三写入操作。
- 如需反馈，提供应用标识、状态、检测原因及脱敏异常类型；不要上传真实授权值、机器标识或完整配置。
