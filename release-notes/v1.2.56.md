# LicenseRecover v1.2.56

This release makes DS01xx legacy .NET recovery failures explicit and prevents unsafe success reporting. It does **not** enable automatic legacy license write-back.

## Fixed

- One-click recovery for DS0101/DS0107 reports **[DOTNET_LEGACY]** rather than UNKNOWN.
- Legacy detection explains that a coexisting uppercase `ITMC.Regedit.dll` does not prove the active protocol is modern.
- Batch **recommended recovery** no longer maps DS01xx to an implicit `--block-net` operation or marks network blocking as authorization success.
- GUI single/batch views label legacy automatic write-back as unsupported rather than ready.
- Explicit manual operations (including user-selected network configuration and advanced scan) are not changed.

## Verification

- Added DS0101-style dual-assembly smoke tests for fail-closed classification, named failure stage, unchanged configuration/files, and batch failure status.
- Reviewed the user-provided DS0101 deployment out of tree; proprietary DLLs and data were **not** committed.
- Windows/.NET Framework and IIS native authorization success remain **unverified**. Existing vendor-authorized registration remains required.

## Upgrade notes

- `[DOTNET_LEGACY]` is an unsupported-operation diagnostic, **not** a recovered license or a successful DLL patch.
- Users who rely on the old explicit `--block-net` mode can still access it separately, but this does not create a valid authorization.
