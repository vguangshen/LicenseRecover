# LicenseRecover v1.2.35

本版继续修复真实 YX030101 小写 `itmcRegedit.dll` 注册链在 v1.2.34 中仍停留于 `GENCODE / TargetInvocationException` 的问题。

## 根因

v1.2.34 已把目标注册组件放进与站点一致的 AppDomain：`ApplicationBase=站点根目录`、`PrivateBinPath=bin`、`ConfigurationFile=目标 web.config`。但真实 YX030101 仍在 `RegID -> getRegNo()` 反射调用处失败。

对已恢复的小写 `itmcRegedit.dll` 继续核对后确认，`getRegNo()` 的第一步就是 `HttpContext.Current.Server.MapPath("~/Register.xml")`，异常路径里也会再次调用同一个 `MapPath`。v1.2.31-v1.2.34 使用三参数 `SimpleWorkerRequest` 并依赖手工设置 `.appPath/.appVPath`，在手工创建的目标 AppDomain 中仍可能得到不可用的 `Server.MapPath`；因此真正的内部异常会被反射包装成泛化的“调用的目标发生了异常”。

## 修复

- 目标 AppDomain 中不再预设 `.appPath/.appVPath`。
- 改用显式绑定虚拟根 `/` 与真实网站物理根目录的五参数 `SimpleWorkerRequest`，让 `~/Register.xml` / `~/config.xml` 由 worker request 自己解析。
- 在调用目标注册组件前增加强制 MapPath 自检；`Register.xml` 与 `config.xml` 必须精确解析到目标网站根目录，否则 fail-closed，并直接给出实际映射路径。
- `GENCODE` 无显式 `--seq` 时先在 Host 控制下复现一次目标 `AppReflection.GetRegNo()`，只做读取探测、不写授权；如果反射内部仍失败，会递归拆开 `TargetInvocationException` / `TypeInitializationException`，输出真实异常类型、消息和堆栈，不再只剩“调用的目标发生了异常”。
- 正常 helper 的 `gencode -> doreg -> verify` 流程保持不变；不修改目标 DLL，不改变申请号、离线授权码、`DoRegistry()`、`CheckReInfo()` 算法。

## 新诊断

正常情况下日志应新增：

- `[ASPNET_HOST] mapPath Register.xml=...\\YX030101\\Register.xml`
- `[ASPNET_HOST] mapPath config.xml=...\\YX030101\\config.xml`
- `[ASPNET_HOST] target request-code probe=OK; hostIdLength=16`

若目标 `getRegNo()` 仍失败，Host 会直接输出具体内部异常，而不是泛化的 `TargetInvocationException`。
