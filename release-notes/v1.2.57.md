# LicenseRecover v1.2.57

This maintenance release improves self-update recovery and removes confirmed legacy scaffolding without changing the supported native authorization workflow.

## Reliability and safety

- Updating is now journaled: a failed installation removes newly created files/directories and restores overwritten files and the previous VERSION.txt.
- The installer verifies restored file contents after rollback and preserves the on-disk backup directory if rollback itself fails.
- Regression tests simulate an interrupted copy and check for a clean rollback, preserved user settings, and no leftover temporary journal.
- Existing ZIP path validation, SHA-256 download verification, and write-back safety checks remain.

## Simplification

- Removed six obsolete one-time version-migration scripts, the dead legacy `productMainFor` placeholder, and unused backup-cleanup Swing injection entry points.
- Retained the supported backup-cleanup engine, single-app recovery, batch recovery, manual advanced compatibility paths, and Java 8 compatibility.
- Aligned .NET/Java directory detection between the general detector and one-click engine.
- Consolidated daily file logging into one synchronized writer.
- Reused one obsolete-launcher cleanup policy, and added named GUI component anchors with legacy fallback.
- Refreshed README.txt for the actual current version.

## Included earlier mainline change

- Removed the manual “已有注册码导入（Java 本地注册）” UI and its dedicated coordinator. Automatic one-click and batch operations remain available for supported targets.

## Compatibility and verification

Java 8 smoke tests, synthetic updater failure/rollback tests, backup cleanup self-test, Windows .NET hosted-chain integration tests, native launcher packaging, and release checks are required before publication.

DS01xx legacy .NET automatic write-back remains unsupported. No new real IIS/vendor-provided authorization success is claimed. Keep the existing backup before upgrading.
