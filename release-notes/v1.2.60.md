# LicenseRecover v1.2.60 RC1 — batch scan responsiveness

**Release candidate / local testing.** The latest verified stable remains v1.2.59. This candidate changes only the batch scan user interface and diagnostics, not license generation, recovery logic, native DLL writeback, or network-blocking behavior.

## Fixes

- Batch scanning no longer persists messages synchronously on the Swing event-dispatch thread; the log appears immediately and the disk log is written by an independent daemon writer.
- Each subdirectory's read-only metadata inspection has a 20-second limit so that a stalled Java JAR or .NET assembly scan cannot keep the entire batch at **0 / N**.
- Timed-out/error rows are clearly labeled and excluded from batch execution. Later applications continue to be listed and scanned.
- At most four lingering timed-out read-only scanner threads may remain; further deep inspection is skipped rather than spawning unlimited threads.
- Batch scanning now uses the local-only application detector, so the scan cannot accidentally classify a non-application subfolder by looking at the parent site's files.
- Added regression smoke tests for bounded inspection, continuation after a timeout, and non-blocking GUI file logging.

## Validation
