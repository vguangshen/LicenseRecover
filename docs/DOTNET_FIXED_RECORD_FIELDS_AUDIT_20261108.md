# .NET 固定位置记录的只读字段审计（2026-11-08）

本轮只读取已核对指纹的副本，恢复方法体并在独立实现中核对数据，没有装载厂商程序集、调用注册方法或执行原生桥接。输出不包含实际密钥、授权载荷或机器标识。

## 构建与范围

受保护兼容组件 `35e40be423f9ea8493edc29bbdfd406a030309241d6ec8c2f1ae3975ef7e5b5f` 的 `CheckReInfo`、`CheckLocalReg`、机器号、密码、记录构造及硬件读取等 19 个方法体已恢复并校验长度及异常表。另一兼容组件 `e684d265332af25ccc3449c38a38f024ecbf87353b9c48710c5ae2b2433c5183` 的 13 个关键方法及属性、局部变量、栈和异常边界与该恢复逻辑一致。

这些恢复结果支持 **RECOVERED_FIXED_FIELDS** 局部诊断，不支持原生/JIT 全路径接受证明。网站产品名不同不能用来推导兼容记录密码；后者由各组件类型初始化器的实际常量证明。当前两构建复用同一个已审兼容解密参数和固定字段引擎。

## 与现代 JSON 记录区分

相同密码族下可以同时存在现代 JSON 包装记录和固定位置记录。先识别解密后的结构，再应用对应字段规则；解密成功不能直接认定 JSON，更不能直接认定授权通过。

已恢复固定分支比较记录 `[6:22]` 的机器字段与普通硬件算法，并要求 `[30:40]` 的到期日严格晚于当前日。它不采用现代 CPU 覆盖号，也没有总次数或开始日期是否已到的许可比较。成功后的记录转换还读取并发数、开始日期、联网字节、班级数和已用次数，因此解析失败不能冒认这些字段均有效。

独立读取保留原有 CPU 最后一项、磁盘首个正签名和首块主板序列号等顺序、空值与主机名回退规则。两份独立实现对当前副本得出相同的布尔比较结果，未输出原值。

## 安全与稳定性

恢复的原生本地成功分支会调用记录构造并写入 `Register.xml`；机器读取还可能写日志，因此没有将原方法接入扫描。生产扫描只使用纯数据转写，不消耗次数、不执行硬件狗、不访问授权服务器、不写注册文件。

普通本地核心检查也不再因为网络/HASP 优先而跳过记录读取。即使现代本地字段全部匹配，非已审核本地优先分派仍只能给出局部 `SATISFIED`，不能变为完整入口接受。文件及组件变化继续撤回结论。

所有实际结果保留 `Authorization.UNVERIFIED` 和 `CodeIntegrity.UNKNOWN`；没有补造可信原版/Patch 文件对。
