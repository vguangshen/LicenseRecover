# LicenseRecover v1.2.78

## PT0402–PT0405 Java one-click registration recovery

- Java PT deployments with no root `config.xml` may return an empty native `getRegInfo().getRegStr()` even when the target `RegisterMain` class and its three-argument constructor load correctly. Previously this stopped at `[JAVA_MODE]` before calling `doRegistry()`.
- During explicit PT one-click or batch recovery, use the target plan's RegStr first, then target-native RegStr, and if both are absent use the PT root directory name (`PT[0-9]{4,6}`) as a single-token last resort. The configured System/module list is not implicitly combined, and existing non-PT rules remain unchanged.
- The fallback passes through the target registration Java helper with the proven constructor and base path. The code must complete native authorization write-back and a fresh-JVM verification before displaying success. Backups and rollback remain enforced, including if optional backup was disabled.
- Add synthetic subprocess tests for PT0402, PT0403, PT0404, PT0405 and the six existing scope-precedence, failure and preview scenarios. These tests validate the integration logic, not the proprietary PT business runtime.
- Retain the prior Java Way 3 behavior from v1.2.77; this change does not remove or rewrite Way 3.

## Verification scope

A prior Windows source verification succeeded for the PT fallback changes on an alternate branch. The v1.2.78 port is separately tested through GitHub Actions. Real PT installations and full business startup have not been independently verified. A missing registration record is not proof that a synthetic directory ID is accepted by the vendor's runtime.
