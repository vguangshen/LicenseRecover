# LicenseRecover v1.2.0

v1.2.0 把原来面向实现细节的“方式一 / 方式二”整合为面向用户的 **一键恢复授权** 主流程：选择应用目录后，由工具自动识别应用、取得本机身份、生成本地授权、写入，并在完成后重新读取授权做自校验。

## 一键恢复

- 默认 GUI 新增大按钮 `一键恢复授权`，主流程变为“选择目录 → 一键恢复 → 自动验证”。
- 原“方式一 / 方式二”仍完整保留，但默认折叠到“显示手工工具”中，作为兼容与排障回退。
- 支持“自动备份”和“只预览，不写入”。
- 日志会显示自动识别出的应用类型、SoftVersionID、机器身份、Adapter 与验证结果。

## Java

- Java 应用直接复用已验证的本地 `regName` 流程。
- 自动调用目标应用自己的授权类取得本机身份并生成授权。
- `RegeditInfo.UserID` 继续固定为 `fwq`。
- 自动写入对应 `config.xml`，并调用目标应用的 `RegisterMain.checkReInfo()` 自校验。

## .NET / YX0302

- 首个自动 .NET Adapter 支持已静态确认的 `YX0302xx + ITMC.Regedit.dll` 系列。
- 不再要求网站注册页面可见；即使应用以前已经本地激活，也可由工具直接调用目标授权组件重新生成本机注册申请号与离线授权码。
- 从原申请号解析真实 16 位 `RegID`，然后按目标 `ITMC.Regedit.dll` 的原生本地授权格式重新构造 `RegeditInfo`。
- `regName` 使用目标算法兼容的 `DES/CBC/PKCS5Padding`，密钥为 `*ITMCYX0302OK*`，Key/IV 与原组件一致。
- 新 `regName` 明确写入 `UserID=fwq`，解决原 `DoRegistry` 不调用 `set_UserID`、最终生成 `UserID=null` 的问题。
- 同步处理历史配置里重复的 `<reg>` 节点，避免旧 `regName` / `WebSerUserID` 与新授权冲突。
- 写入前建立经 SHA-256 校验的备份；写入过程中出错会恢复事务前内容。
- 写入后调用内置 .NET helper 的 `verify` / `CheckReInfo` 路径重新读取授权；验证失败会自动回滚本次改动。

## 安全边界

- v1.2.0 的自动 .NET 写入只对已确认的 YX0302 Adapter 启用。
- DS01xx 以及尚未确认协议的其它 .NET 版本不会套用 YX0302 算法，工具会停止自动写入并提示使用高级/手工工具。
- 后续版本可继续把这些产品的专用 Adapter 接入同一个“一键恢复授权”按钮，而无需再次改变用户操作方式。

## 兼容性

- Java 8 仍为 Java 基线。
- Windows 7 / Windows Server 2008 兼容边界保持不变。
- `LicenseRecoverGUI.exe` 仍是推荐 Windows 入口，继续使用内置 JRE、版本显示和 GitHub 在线更新。
- `run_gui.bat`、旧 GUI 和手工方式一/二/三入口继续保留。
