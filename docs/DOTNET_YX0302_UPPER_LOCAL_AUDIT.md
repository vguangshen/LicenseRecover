2026-11-07 在独立样本副本中复核。所有厂商程序集仅作 PE/CIL 静态读取；没有加载或执行其构造器、注册方法、网络、硬件狗或写回代码。FOAP 恢复产物仅保存在仓库外分析目录，不部署、不公开厂商二进制。

## 这次漏掉的证据

YX030107 当前根配置采用本地优先模式，其载荷已经可以按照当前大写注册器的 DES 规则解密，剥去前后各六字符后，得到现有严格解析器支持的 JSON RegeditInfo。此前兼容协议诊断无条件停在“小写 VM 待审核”，即使当前实际记录已经改为上位现代协议，也没有运行已有独立本地谓词。

解密成功、JSON 字段存在或配置模式为本地优先均不证明授权通过。现代本地判据仍需独立验证产品、当前机器或可信覆盖号、日期、无限次数及当前产品模式；失败也不证明其他授权方式无效。

## 大写本地条件已知，整个网站入口仍未闭合

恢复后大写 `RegeditMain.CheckReInfo` (`06000063`) 在 `regType=1` 的 `00CD..00D7` 首先调用 `CheckLocalReg`，成功即返回“不需要注册”，不进入其网络/HASP 回退。

`CheckLocalReg` (`06000070`) 的 `00D7..018B` 使用本产品密码解密根配置记录、去六字符包装并解析 JSON；`018D..0200` 比较机器；`0205..0292` 比较日期；`0296..02B5` 在无限次数 `-1` 分支直接成功。有限次数分支有写回，未加入只读正向判断。`getRegNo` (`06000074`) 的 `0006..005F` 先核验 CPU 绑定覆盖号，失败才走原机器规则；共享独立身份检查仍必须满足这一区别。

网站 `PubBase.CheckReg_`（构建 A `06001909`）在大写成功后，将上位对象的十二项字段复制到小写 `RegeditInfo`，不调用小写 `CheckReInfo`。这些小写字段的 getter/setter (`0600006A..06000081`) 是明确的 backing-field 访问。

但小写 **`RegeditInfo` 构造器 `06000082` 仍经过受保护分派器**，网站 `.cctor`（构建 A `06001945`）在初始化静态注册对象时调用它。构造器转入方法 `06000193`，后续 `060001B1` 调用动态生成的方法；仅有外层 FOAP 的完整恢复不能证明实际构造语义。该缺口属于接受链的一部分，不能笼统排除为一般运行健康问题。

本轮继续按照托管解码分支静态恢复该构造器的 92 字节方法体（12 字节头、80 字节 CIL，SHA-256 `e56b2b695cc3b90dd47022360e7917291ca5d507b8ad40724c533b46a1550828`），并验证长度及全部元数据引用。这个分支的明文仅初始化六个字段：默认产品字符串、两天前的日期、并发数 20、天数 10、空产品范围与班级数 1，以及调用 `Object` 构造器；未包含授权验证、文件、注册表或网络操作。对应 token 重写器通过 `DynamicILInfo.SetCode` 构建方法。

这个进展仍不能直接关闭所有初始化边界：保护器的密钥处理还有原生桥接分支，尚未证明它与上述托管分支在当前运行环境中严格等价，也没有用执行厂商方法补齐。当前代码不将单分支静态恢复提升为整个网站已证明接受。

因此，本轮只允许报告“上位本地核心条件通过，网站 VM 初始化/兼容入口仍待核”的局部证据。即使共享现代谓词得出正向结果，也必须降为 `LocalCondition.SATISFIED`、`Acceptance.UNVERIFIED`，保持灰色；不得声称已经获得完整授权入口接受、厂商原生有效或确认 Patch。

对仍为非 JSON、未知分派或受保护载荷的同族应用，继续保留兼容协议诊断。不能拿 YX030107 当前记录替代其他应用的当前输入，也不能把另一个版本的固定位置旧格式套到此 VM 构建。
