# YS01 双注册组件的现代本地分支审计

YX0102 同时包含大写现代注册组件和小写旧协议组件。当前样本的根 `config.xml` 中载荷属于 **YS01 现代 JSON/DES 协议**，并非小写 `*MarketOK*` 固定位置记录。v1.2.72 只选择了兼容构建诊断，以小写格式解码这一现代记录，因而显示“本地格式未通过”。该结果不能解释为应用未激活。

本轮只在独立副本上静态读取 CIL、元数据及配置，未加载或执行厂商程序集，未调用注册、恢复或 Patch。解密内容、机器号和实际授权值不进入源码、测试或报告。

## 现代本地注册条件

大写注册组件的下列方法与此前已审 DS0101 构建的相应 CIL 完全一致：`CheckLocalReg`、`CheckReInfo`、`getRegNo`、`get_lastNOpsw`、`GetCpuid.Getid`、`Computer.GetCpuID`、`GetDiskID`、`GetBoardID`。还核对了 `RegeditMain` 的构造器、类型初始化器、产品 getter、双参数 DES 解码，以及 `RegeditInfo` 的日期、机器、产品范围及次数 getter/setter，均为相同 CIL。不是只比较方法名或接口。

- `CheckReInfo`（`0x06000063`）在根配置 `regType=1` 时首先调用现代 `CheckLocalReg`；本地成功直接返回“不需要注册”，不进入后续网络/HASP 分支。
- `CheckLocalReg`（`0x06000070`）读取根配置记录，使用 `*ITMC` + 当前产品 + `OK*` 的已审 DES/MD5 规则解密，剥去前后各 6 个字符，再按 JSON 解析。
- 接受条件仍使用共享谓词：当前产品身份、独立本机身份、日期、无限计次及网站当前模式全部符合。并非只要求能解密、字段非空或存在授权记录。
- `getRegNo`（`0x06000074`）的覆盖号、WMIC 及普通 WMI 回退规则与此前已审现代实现一致；未知环境或身份规则继续待核。
- 注册构造器（`0x06000061`）接收网站生成的校验参数，按产品相关密码解密后设置 `Checkx`。该构造器还可能创建注册/配置文件，因此禁止通过实际执行构造器验证这个参数。

## 网站当前模式与父产品边界

网站 `ITMC.funpublic` 的类型初始化器（`0x060002E4`，CIL `0x003E..0x0043`）明确将 `ProName` 设为 YS01；`get_SoftVersionID`（`0x0600022B`）从根配置读取当前模式。

`GetProVersion`（`0x0600023D`）先收集兼容父产品关系，随后在 CIL `0x009D..0x00DC` **总会补入当前产品和当前模式**。无需猜测某个父产品已激活。`CheckSoftVersionID`（`0x0600023C`）还向候选模式列表加入当前模式，并按已审大小写无关子串条件检查。

本轮另外核对了兼容数据库读取的异常表，而非假设数据库始终健康：`GetRegisterVersionList`（`0x060013D3`）对 CIL `0x0006..0x00CA` 使用 `System.Exception` 捕获；处理区 `0x00CA..0x00D3` 创建并返回空列表。该版本的 catch 不写日志，数据库读取失败后仍能执行上述当前产品补入步骤。普通内存耗尽、CLR 故障、文件系统运行健康等不属于授权条件证明。

`CheckReg`（`0x0600023B`）在候选产品的注册条件及模式条件通过后，于 CIL `0x0179..0x018B` 返回“不需要注册”并退出循环。只有大写条件失败才进入小写兼容组件。共享独立谓词证明当前产品的本地接受条件，不执行整站、不观测 IIS 缓存，也不保证所有业务功能正常。

## 扫描行为

现代分支获得完整构建绑定后，应先运行既有共享现代正向谓词。未通过时保留具体的现代局部观察，并补充旧协议/其他来源诊断；不能因旧解码失败覆盖一个已经解析清楚的现代机器不匹配或日期观察。

独立的载荷格式识别只用于分派和说明。不论识别出现代 JSON、旧记录还是未知格式，单靠格式都不得创建绿色、原生有效、原生无效或确认 Patch。配置或绑定组件变化必须撤回本次结论。

当前副本独立执行共享正向谓词已取得 `VERIFIED_USABLE / SATISFIED`，原生授权和整体代码来源仍分别为 `UNVERIFIED / UNKNOWN`。完整最终 ZIP 的测试由本轮统一打包验证记录给出，本文件不将源码探针结果冒充发布包验证。
