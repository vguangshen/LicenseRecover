# LicenseRecover v1.2.33

本版继续根据真实 Windows / .NET Framework 上 YX030101 的 v1.2.32 回归修复小写 `itmcRegedit.dll` 注册链。

## 根因

v1.2.32 已经成功在同一个 ASP.NET AppDomain 中调用 `ParseArgs -> RunDirect`，并保留 `HttpContext.Current`。但 `RunDirect` 仍运行在 LicenseRecover 工具自己的 AppDomain 中，因此程序集基础目录仍然是 `LicenseRecover.NET`。原 helper 在加载小写 `itmcRegedit.dll` 时会优先按自身目录探测，真实机因此报错并尝试加载：

`...\LicenseRecover.NET\itmcRegedit.dll`

而目标注册组件实际位于：

`<目标站点>\bin\itmcRegedit.dll`

YX030101 的完整 `bin` 并未缺失，失败属于 helper 的程序集解析目录错误。

## 修复

- ASP.NET host 在调用原 helper 前，为当前 AppDomain 安装仅针对目标 `runtimeDir/bin` 的 `AssemblyResolve`。
- 预加载目标 `bin\itmcRegedit.dll`，让 helper 的按名称加载命中与网站完全相同的注册程序集。
- 当该程序集的依赖项未在工具目录中找到时，解析器继续从目标 `bin` 目录加载 `.dll` / `.exe` 依赖。
- 增加 `[ASPNET_HOST] preload target registration assembly=...` 与 `[ASPNET_HOST] target-bin resolve: ...` 诊断，后续可以直接看到实际程序集来源。
- 不复制、不修改目标 DLL；不改变申请号、离线授权码、`DoRegistry()`、`CheckReInfo()` 算法。
- 大写 `ITMC.Regedit.dll` / `LicenseRecover.NET.Modern.exe` 回退链保持不变。

## 验证重点

YX030101 日志应显示目标程序集从 `D:\MCPanel\web\YX030101\bin` 加载，不应再出现从 LicenseRecover 自身目录查找 `itmcRegedit.dll` 的错误。之后若仍失败，错误应来自目标注册组件自身或其真实依赖，可继续按结构化日志定位。
