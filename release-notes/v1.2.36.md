# LicenseRecover v1.2.36

本版继续处理真实 YX030101 小写 `itmcRegedit.dll` 链在 v1.2.35 中暴露出的 ASP.NET 宿主问题。

## 这次确认的根因

v1.2.35 已把异常提前到 `ValidateMapPaths()`，真实 Windows/.NET Framework 返回：

`不能使应用程序相对虚拟路径“~/Register.xml”成为绝对路径，因为应用程序的路径未知。`

这说明失败仍发生在 LicenseRecover 自己建立的 ASP.NET 宿主层，目标 `itmcRegedit.dll` 的 `getRegNo()` 尚未真正开始。

对 .NET Framework `System.Web.HttpRuntime` 的实现核对后确认：只有 AppDomain 存在 `.appDomain` 标记时，`HttpRuntime` 才会读取 `.appPath` / `.appVPath` 并建立 `AppDomainAppPath` / `AppDomainAppVirtualPath`。v1.2.34 只写了路径但没有 `.appDomain`；v1.2.35 改用五参数 `SimpleWorkerRequest`，仍不能让手工创建的 AppDomain 被 `HttpRuntime` 识别为已知 ASP.NET 应用。

## 修复

- 在目标 AppDomain 首次初始化 `System.Web` 前写入完整 ASP.NET 绑定：`.appDomain`、`.appId`、`.domainId`、`.appPath`、`.appVPath=/`。
- 恢复使用“应用路径已知”场景的三参数 `SimpleWorkerRequest`，避免五参数构造器与预置应用路径互相覆盖。
- 保留 v1.2.35 的 `~/Register.xml` / `~/config.xml` MapPath 强制自检；只有两者精确映射到真实目标站点根目录后才允许进入目标注册组件。
- 保留只读 request-code probe 与异常递归拆包；MapPath 一旦通过，如果 `getRegNo()` 仍失败，下一条日志会直接显示目标组件内部的真实异常。
- 不修改目标 DLL，不改变申请号、离线授权码、`DoRegistry()`、`CheckReInfo()` 算法；小写优先、大写回退规则保持不变。

## 新诊断

正常情况下应先看到：

- `[ASPNET_HOST] aspnet-bindings appDomain=... appVPath=/ appPath=...`
- `[ASPNET_HOST] mapPath Register.xml=...\\YX030101\\Register.xml`
- `[ASPNET_HOST] mapPath config.xml=...\\YX030101\\config.xml`

随后才进入 `target request-code probe` 与正常 `gencode -> doreg -> verify`。
