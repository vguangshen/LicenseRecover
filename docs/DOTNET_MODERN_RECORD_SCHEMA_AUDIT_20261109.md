# .NET 现代记录的完整对象边界（2026-11-09）

现代本地检查先调用 JSON.NET 构造整个 `RegeditInfo`，再计算机器、期限与次数。无限次数只跳过计次业务，不能跳过其他属性的反序列化。此前只检查许可条件字段，可能将目标实际无法构造的记录判成通过。

## 精确模型与独立验证

本轮静态检查既有五个已审核大写注册组件的元数据；它们均具有同样十四个公共可序列化属性，没有该模型/属性的额外序列化特性或公共字段。组件仍须匹配 `LicenseRecoverReadOnlyDotNetCatalog` 的完整已审构建，不能仅凭这些属性名套用本地接受证明。

| 类型 | 规范属性 |
| --- | --- |
| String | ProName、RegID、UserID、RegStr |
| Int32 | ClassNum、TotalTimes、UserTimes、MaxCon、CountDay |
| Boolean | Net |
| DateTime | BeginDate、EndDate |
| Int64 | beginDate、endDate |

测试只运行自编同结构模型及精确版本的 JSON.NET，不装载厂商类型。修复前，损坏/溢出的 `UserTimes`、损坏的 `BeginDate`、`Net`、`MaxCon` 可被独立谓词忽略，而模型反序列化拒绝；非零小写到期日期还会改变实际 getter 结果。这些案例现均不能升为入口接受。

生产原语先限定规范属性及其已审核类型、整数范围和日期格式，再计算许可条件。未知属性、大小写别名、类型扩展、引用元数据和需要未审强制转换的值均待核。缺失可选属性保留已审模型默认值；原有正向必需字段仍单独检查。该范围可以保守拒绝目标可能接受的其他转换，不能反向宣称其原生授权无效。

## 大小写日期是不同属性

`BeginDate/beginDate`、`EndDate/endDate` 是模型中真实存在的不同属性，不能将小写属性一律视为 JSON 别名。小写值为零时，getter 沿用大写日期；非零时会调用历史转换，覆盖大写值。

转换将 Int64 的十进制文本追加四个零，再解析为 Int64 tick 增量，并加到 `TimeZone.CurrentTimeZone` 转换的 1970 本地历元。它既存在解析溢出、DateTime 范围边界，也依赖 .NET 历史时区规则。忽略非零小写值可能把大写未来日期误当作实际到期日期。

当前只支持小写字段缺失或规范 Int64 零值；非零值输出明确的 getter/历史时区待核原因，不沿用大写日期通过结果。本轮真实现代记录的两项小写日期均为零，规范字段与类型符合该限制。该样本观察不构成未来任意记录适用的证明。

检测不执行厂商 getter、构造器或 JSON.NET，不输出记录、密钥、机器标识或用户字段值。它只使用既有独立只读解析器与纯字段判据；本轮修复也不把局部解析成功升级为原生有效或可信 Patch。
