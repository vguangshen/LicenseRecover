# LicenseRecover v1.2.9

本版本完成 Java classes-config 平台的 RegStr 安全恢复链路，并根据 QT100101 真实业务代码解除其不必要的“待确认”状态。

## QT100101

对用户提供的真实 QT100101 应用代码脱壳分析后确认，启动授权判断最终检查 `RegeditInfo.getRegStr().contains(RegisterContant.versionID)`，而该项目 `systemConfig.yml` 的 VersionID 为 `QT100101`。因此 `QT100101` 是经过实际业务门槛验证的最小 RegStr，而不是猜测或 44 项通用回退。

v1.2.9 中 QT100101 将显示：

- 类型/授权代际：`Java / QT1001系列 / classes-config`
- SoftVersionID：`QT100101`
- 授权族：`QT100101`
- 运行校验ID：`QT100101`
- RegStr：`QT100101`
- 状态：`待处理`（可安全自动恢复）

## 现有本地授权 RegStr 恢复

当 classes-config 平台没有静态 `regInfo` 时，程序会检查 classes、webapp 根、data 与 WEB-INF/lib 下的 config.xml。只有同时满足以下条件才进入只读恢复：

1. `regType=1`；
2. 存在非空 `regName`。

随后通过该应用自己的 ITMCReg（Virbox 版本会临时脱壳到临时目录）创建 RegisterMain，并只调用 `getRegInfo()` 读取原 `RegStr`。不会调用 `checkReInfo()`。

如果多个本地配置恢复出的 RegStr 不一致，程序不会任选其一，而是继续保持待确认。

## 联网安全边界

- `regType=3` 永远不会进入动态 RegStr 探测，因为该分支可能访问厂商授权 WebService。
- 没有旧本地授权的 QT40101 仍保持待确认；若未来机器上保留有效 `regType=1 + regName`，扫描可离线恢复其真实 RegStr。
