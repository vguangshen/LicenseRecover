# LicenseRecover v1.2.5

本版本根据实际 DS50109 与 YX030506 安装样本，修正 Java classes-config 平台的授权模型。

## 授权族 / 运行校验ID / RegStr

此前界面把 classes-config 平台笼统显示为“新式”，并用一个 ProName 字段同时表达本地注册产品族与应用启动时的 RegisterMain 校验ID。实际样本证明两者并不总是相同。

- DS50109：本地注册业务使用 `RegisterMain("DS501")`；应用启动使用具体 `DS50109` 执行 `RegisterMain.checkReInfo()`，且要求 RegStr 包含当前 versionID。
- YX030506：本地注册页面使用 `RegisterMain("YX0305", ...)`；应用启动从配置的 SoftVersionID 读取具体 `YX030506` 执行 `RegisterMain.checkReInfo()`；配置明确声明 `regInfo=QT100101,QT100102`。

因此 v1.2.5 将 Java 识别拆成三层：

1. **授权族**：厂商本地注册页面 / doRegistry 路径使用的产品族；
2. **运行校验ID**：应用启动时 RegisterMain.checkReInfo() 使用的具体ID；
3. **RegStr**：实际授权功能/版本项。

## 界面与批量

- 已确认样本显示 `DS501 / classes-config`、`YX0305 / classes-config`。
- 单应用与批量页都分别显示“授权族”和“运行校验ID”。
- 尚未有真实样本支持的 classes-config 产品显示为 `通用 / classes-config`；不会仅凭产品名猜测 QT40101 等平台的授权族。

## 执行逻辑

- DS501xx 直接授权重建使用具体 SoftVersionID 作为运行期 ProName；配置没有 regInfo 时，RegStr 使用具体 SoftVersionID。
- YX0305xx 直接授权重建使用具体 SoftVersionID 作为运行期 ProName；RegStr 优先使用 classes/config.xml 显式 regInfo。
- 手动“生成离线授权码”路径分别使用已确认的本地注册族 `DS501` / `YX0305`。

原有 YT、XMT、QT30xxx、DS28、.NET、一键恢复、批量异常隔离与 v1.2.4 更新器逻辑保持不变。
