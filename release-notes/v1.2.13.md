# LicenseRecover v1.2.13

本版统一收紧 Java 与 .NET 注册识别策略：**注册代号、运行 ProductID/ProName 与 RegStr 必须由目标软件目录本身提供证据；无法确认时直接阻止自动恢复，不再使用默认兜底值。**

- Java：新增目标目录注册元数据解析，优先从应用自身 `Global.class` / `RegisterUtil.class`、`data/config.xml`、`WEB-INF/classes/config*.xml` 与可验证的已有本地授权中确定注册身份与授权项。
- Java：移除执行计划中的 44 项 `FALLBACK_ALL_NUMS`，并停止使用 `QT1001`、`QT04`、`YT001`、`YT00129 -> QT0420`、`VersionID -> RegStr` 等固定/推测式执行兜底。
- Java：单应用、批量、旧 GUI、CLI 与 `--gencode` 统一走 fail-closed 目录证据计划；历史兼容映射最多用于诊断，不再足以触发写入。
- YT00138：运行注册 ID 由目标程序自身注册分派逻辑解析，而不是在 LicenseRecover 中硬编码；目标目录可确认时使用其真实映射，无法确认则拒绝 Patch。
- .NET：ProName/ProductID 必须从目标 `ITMC.Web.dll` 解析；RegStr 必须从目标 DLL/目录证据解析，不再回退到 `VersionID` 或默认产品列表。
- DS01xx 旧 .NET 协议取消固定 `itmcIEC` 执行值，必须由目标 DLL 实际确认产品标识后才能生成/写入。
- GUI、CLI、批量与 .NET 原生 `gencode -> DoRegistry -> CheckReInfo` 链路统一执行同一严格策略。
- CI 新增防回归检查：若重新引入固定 .NET 产品名、Java catch-all RegStr 或 GUI 默认产品号，正式 Verify 将直接失败。
- 保留写前备份、原生校验以及失败自动回滚；严格识别失败时不会修改目标软件注册配置。

> 行为变化：部分过去依赖内置兼容表“猜测”注册信息的软件，现在如果目录中缺少足够证据，会显示未确认并阻止自动恢复。这是预期的安全行为，用于避免错误 ProductID/RegStr 导致程序启动失败。
