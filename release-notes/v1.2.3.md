# LicenseRecover v1.2.3

This release fixes the Java batch-scan failure introduced by the v1.2.2 authorization-plan UI and adds verified support for the DS28 Java generation observed in the DS2802 sample.

## Batch Java detection

- Java authorization-plan preview is now file-only and no longer depends on loading `LicenseRecover.class` or the selected application's `ITMCReg` classes into the GUI process.
- This fixes the case where batch scan stopped at the first Java application with `NoClassDefFoundError: LicenseRecover`.
- Each child directory is now isolated during batch scan. A malformed or previously unseen application is reported as a detection error without aborting the remaining rows.
- The batch progress summary now reports total directories, detected applications, unrecognized applications, and detection errors.

## DS28 Java authorization

- DS28xx applications now resolve the vendor registration `ProName` to `DS28`.
- When no explicit `regInfo` is present, a DS28xx application's effective `RegStr` is the active `SoftVersionID` (for example `DS2802`) instead of the generic fallback list.
- The single-app authorization plan and batch preview show `DS28 / data-config`, `ProName=DS28`, and the active DS28xx product id consistently with the real recovery path.
- Existing root-config handling remains enabled, so applications that keep `data/config.xml` continue to receive both compatibility config targets and the application's own `RegisterMain.checkReInfo()` verification path.

## Sample evidence used for this fix

The supplied DS2802 application sample showed:

- `SoftVersionID=DS2802` in the application's data configuration.
- The protected application runtime initializes `Global.PRODUCT_NUM` as `DS28`.
- The startup registration path constructs `RegisterMain` with `Global.PRODUCT_NUM` and requires the returned `regStr` to contain the active system product id (`DS2802`).

## Compatibility

- Java 8 source/runtime compatibility is retained.
- Virbox-protected registration classes continue to use the existing temporary-unpack execution path.
- Windows 7 / Windows Server 2008 remains within the existing GUI compatibility boundary.
- The portable package continues to expose only `LicenseRecoverGUI.exe` as the root user-facing executable.
