# LicenseRecover v1.2.1

This release focuses on the self-update path and the Windows distribution entry point.

## Update experience

- Adds a visible Swing download progress window for self-updates, including percentage and downloaded/total size when GitHub provides `Content-Length`.
- Shows separate download and SHA-256 verification states instead of appearing to hang during an update.
- Prevents overlapping update checks/downloads from starting at the same time.

## Update reliability

- New-version installers restart `LicenseRecoverGUI.exe` directly and no longer depend on `cmd.exe` / BAT parsing after replacement.
- The slim update archive keeps only a small `run_gui.bat` transition trampoline so pre-v1.2.1 clients can finish their final legacy-style restart.
- The transition BAT no longer uses chained `&&` expressions and prefers the native EXE immediately, avoiding the command-shell errors seen during v1.1.x -> newer updates.
- After the new GUI is running, stale root launchers such as `LicenseRecoverGUI-legacy.exe` and old `run*.bat` files are cleaned up.
- Future updates performed by v1.2.1+ use the native EXE directly for restart.

## Single user entry point

- `LicenseRecover-latest.zip` now exposes exactly one root EXE entry point: `LicenseRecoverGUI.exe`.
- Legacy EXE and BAT launchers are removed from the portable package.
- Internal runtime/helper files remain available for compatibility, including the .NET helper under `LicenseRecover.NET/`; they are not user-facing launch entries.
- CI verifies that the portable package contains one root EXE and no root BAT launchers.

## Compatibility note

An already-installed v1.1.x/v1.2.0 client still uses its old updater code for the download that brings it to v1.2.1, so that one transition download cannot gain the new progress UI retroactively. The v1.2.1 package fixes the old restart path, and all update downloads initiated after v1.2.1 is running use the new progress window.
