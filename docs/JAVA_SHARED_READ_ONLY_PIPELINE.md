# Java 共用只读检测入口与协议参数

2026-11-03 项目复核。Java 由 `LicenseRecoverReadOnlyJavaScanner.scan(root)` 统一收集授权证据；外层扫描器只需在 Java 与 .NET 两个运行时入口之间选择。入口数量的收敛不意味着把不同厂商协议假装成相同算法，也不改变五色证据要求。

## 实际可以复用的部分

当前 17 个 Java 样本中，14 个使用逐字节相同的 J1 注册 JAR（含新提供的 YT00123），另有 DS24 的静态门槛样本和两项 J3 样本。这是已观察组件的共性，不意味着授权状态相同或原版/Patch 来源相同。

J1 本地记录检查已经共用 `LicenseRecoverReadOnlyJavaLocalVerifier.checkLocal`：

- 同一注册模式选择、规范十六进制/DES 包装及扁平 JSON 读取；
- 同一已审核的独立 Windows 机器绑定原语、期限和无限计次条件；
- 同一产品模式包含判断，以及数值字段和输入格式边界；
- 同一“局部失败不能否定其他授权方式、有限计次不消耗真实授权”的规则。

`JavaAlternateVerifier` 的已审核本地正向入口直接调用这个原语，没有为 XMT、DS 或每个版本复制密码、机器或期限算法。不同应用的真实差异由已审启动布局和参数描述：根/库配置位置、构造产品的来源、当前 `VersionID`、任一产品模式集合、产品回退与是否已证明无接受后备。版本/目录名称本身不能选择成功状态。

DS24 的静态门槛证明是不同的事实渠道：完整代码和启动资源证明它的注册与产品门槛默认接受。它不是另一套授权密钥解码，也不能转成可信 Patch 来源。其余 J3、网络/HASP、数据库产品、未审字节码和运行缓存不因共享入口而被假定通过。

## 统一入口的选择与证据优先级

统一 Java pipeline 依次使用已有的静态门槛、本地原语绑定和启动布局绑定。完整当前接受/完整拒绝或真正读取错误及时返回；只有局部事实时保留其边界。全部不适用时同时保留三个内部渠道的具体原因，不把版本、组件或资源失配简化成“未激活”。已有审核表和同次输入复核仍是证据适用条件，协议候选不等于授权证明。

这不是新增按软件名分支。后续同系列版本可复用原语与布局参数；如果仅业务代码变化，也需要确认实际启动/授权调用链和依赖仍满足已审核语义，再补版本证据，而非添加一个目录名判断。保护器、反射、插件、容器共享类路径或外部 JVM 参数改变时，不能仅凭注册 JAR 相同升绿。

## 全面复核中修正的两个共性问题

1. **同一入口类可属于多个完整构建。** 本地 J1 验证器此前命中第一个 anchor 后便选定其完整指纹，新版本即使有另一条已审记录也可能不可达。现在先收集全部匹配入口的候选，再按完整 class/JAR/启动资源选择；同一资源策略的完整首次观察在本次调用内复用，不以目录名选择。冲突的重复完整构建记录保守待核。现有真实指纹值未改变。
2. **完整双读可能跨过期限边界。** 启动布局验证器此前捕获扫描开始的时间，复读大型依赖后仍返回旧的成功结果。现在生产入口在最终匹配的快照后重新读取当前时间并重算条件；测试使用受控时钟模拟跨界，无需等待或消耗真实授权。

这两项都是跨应用的匹配/证据时效问题，不是为某个产品补特判。Java 读取器原有的路径链接拒绝、输入大小上限、中断检查、完整集合指纹、配置双读和未知保持灰色仍保留。双读不是原子文件系统快照；未观测的进程缓存、业务数据库及所有业务功能不在本地接受证明内。

## 验证范围

`LicenseRecoverReadOnlyJavaScannerTest` 覆盖统一入口短路、接受/拒绝/错误保留、布局与本地观察优先级、全部未知时原因保留及强证据不得降级。`JavaLocalVerifierTest` 增加同 anchor 不同完整构建、审核记录顺序无关及冲突记录拒绝。`JavaAlternateVerifierTest` 增加受控时钟跨界撤销旧成功。

这些 Java 单元测试只使用独立临时目录中的合成文件和合成授权数据；没有修改真实软件或样本、执行厂商代码或制造 Patch 文件对。完整构建、两份最终 ZIP 和实样副本的运行结果由项目主验证流程记录，不能以测试进程正常退出替代授权状态证据。
