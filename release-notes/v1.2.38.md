# LicenseRecover v1.2.38

本版针对仅包含大写 `ITMC.Regedit.dll` 的 .NET 应用单独修复运行环境，不再把“大写 DLL”视为“小写 itmcRegedit.dll 的简单改名版”。

## 大写注册链修复

对重新恢复后的大写 `ITMC.Regedit.dll` 进行结构核对后确认，两代组件的运行假设不同：

- 小写 `itmcRegedit.dll` 主要依赖 `HttpContext.Current.Server.MapPath("~/...")`；
- 大写 `ITMC.Regedit.dll` 会直接依赖 `AppDomain.CurrentDomain.BaseDirectory` 访问站点根 `config.xml` / `Register.xml`，并使用自己的 `RegeditMain` / `RegeditInfo` API 表面；
- 大写样本包含 `NewRegistry()`、`DoRegistry(string,string)`、`CheckReInfo(ref RegeditInfo)`、`RegID` / `getRegNo()` 等成员，不能只按小写参数约定处理。

v1.2.37 以前，仅大写链会直接运行 `LicenseRecover.NET.Modern.exe`，其应用基目录可能落在目标 `bin`，与 IIS 实际站点根目录不一致。v1.2.38 改为：

- 仍保持“小写存在则小写优先；小写不存在才使用大写 ITMC.Regedit.dll”；
- 两条链都先进入真实 ASP.NET Hosted AppDomain；
- 小写链继续使用原 `LicenseRecover.NET.exe`；
- 大写链在 Hosted AppDomain 内使用 `LicenseRecover.NET.Modern.exe`；
- 对大写链强制保证 `HostingEnvironment.ApplicationPhysicalPath`、`HttpRuntime.AppDomainAppPath` 与 `AppDomain.BaseDirectory` 都指向网站根目录，而目标程序集仍从 `bin` 解析；
- 因此大写组件读取的是网站根 `config.xml` / `Register.xml`，不会误读或生成 `bin\config.xml`。

## Windows 集成验证

发布前新增独立 Windows/.NET Framework 集成夹具，按已恢复的大写 API 表面构造仅含 `ITMC.Regedit.dll` 的 YX030308 风格站点，并实际执行：

`gencode -> DoRegistry -> CheckReInfo`

测试要求：

- Host 明确选择 `uppercase-ITMC.Regedit` + `LicenseRecover.NET.Modern.exe`；
- Hosted AppDomain 的 `BaseDirectory` 必须等于站点根；
- `Register.xml` / `config.xml` 必须位于站点根，禁止从 `bin` 读取；
- `RegID` / request-code 路径能够在目标站点域中执行；
- `DoRegistry` 写回发生在站点根环境；
- `CheckReInfo(ref RegeditInfo)` 路径完成并返回本地授权有效约定；
- 临时 ASP.NET Bridge 在执行后清理。

该 Windows 集成链在测试分支上已完整通过后，才进入 v1.2.38 发布流程。

## 保持不变

- 恢复前仍先建立临时 Windows Firewall 出站隔离，再调用目标注册组件；
- 默认联网阻断模式仍会把授权 Service 指向不可达本地端点并在写回后再次确认；
- 关键配置继续备份并在失败时回滚；
- 不修改目标 `itmcRegedit.dll` / `ITMC.Regedit.dll` 文件本身；
- Java、.NET Legacy、小写 .NET 链行为不变。
