# LicenseRecover v1.2.48

本版针对用户当前服务器中的真实 YX030506 部署结构修复批量扫描“待确认”。

## 根因

真实部署版同时存在两层身份：

- `systemConfig.yml`: 应用模式 `YX030506`；
- `WEB-INF/classes/config.xml` 的 `SoftVersionID`: `YX0305,QT1001`，这是启动时逐项送入 RegisterMain 的产品列表；
- `regInfo`: `QT100101,QT100102`。

旧逻辑要求 classes/config 的 SoftVersionID 与应用模式完全相等，因此虽然授权族和 RegStr 已识别，运行校验 ID 仍为空。

## 修复

- 不再把 `YX030506` 应用模式与 `YX0305,QT1001` 注册产品列表混为一个字段。
- 对该真实 PRODUCT_ALL_NUM 结构，主运行注册产品确认成 `YX0305`；应用模式仍保持 `YX030506`，RegStr 仍为 `QT100101,QT100102`。
- 只有以下目标自身证据全部成立才允许自动恢复：当前 System 枚举、PRODUCT_ALL_NUM 解析/循环、RegisterMain.checkReInfo/writeRegisterUser 链，以及 RegisterHttpServlet 对 YX0305 的 ProjectSourcesPath/RegisterMain 调用。
- 删除任一关键启动证据的回归测试必须继续得到 BLOCKED，避免把 VersionID 前缀当白名单。

## 真实样本验证

已依据用户提供的精简服务器样本核对配置与目标 class 字节码证据，并完成 Java 8 完整回归和正式构建验证。

预期批量计划：

`AuthorizationFamily=YX0305`  
`RuntimeProductID=YX0305`  
`RegStr=QT100101,QT100102`  
`automaticRecoveryReady=true`
