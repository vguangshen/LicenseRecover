# LicenseRecover v1.2.79

## .NET local UserID consistency

- Fix DS01xx Legacy helper initialization: `RegeditMain.UserID` now uses the same fixed `fwq` local authorization identity as the existing Java and modern .NET helper behavior, instead of `itmc`.
- Reject a purported Legacy restoration when the native `CheckLocalReg(ref RegeditInfo)` record's persisted `UserID` differs from `fwq`. The diagnostic output emits only `match`/`mismatch`, not the stored identity.
- Preserve separate compatibility fields and protocol values, including `WebSerUserID`, the `itmcIEC` product name, and registration cryptographic inputs. The tool does not rewrite target vendor DLLs.

## Regression protection

- Synthetic DS01xx .NET registration stubs verify that NewRegistry is initialized with `fwq`, that the local record persists the identity, and that the validation path rejects a simulated `itmc` identity.
- Distribution assembly checks the original .NET helper and the Modern adapter for the pinned `set_UserID` / `fwq` IL mapping, and checks the newly compiled Legacy source and assembly for the expected identity.
- Rebuilds and packages `LicenseRecover.NET.Legacy.dll` using the repository's existing verified build pipeline.

## Compatibility and scope

This release retains v1.2.78 PT0402–PT0405 Java fallback and previous functionality. Source, synthetic tests, and build checks do not establish that every proprietary DS01xx application and downstream business page works; test authorized installations in an isolated environment and keep backups before replacing an installed version.
