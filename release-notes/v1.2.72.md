# LicenseRecover v1.2.72

修正“入口通过却没有绿色”和“授权成功后看不到 Patch 尚缺证据”的反馈，同时补上真正的代码证据与应用 class 层扫描能力。

- 已审核入口通过项恢复绿色，标签仍为“当前入口条件通过（来源未确认）”。代码证据独立显示，不能把绿色或授权恢复成功理解成已确认代码 Patch。
- 应用根目录下成套比对 class/JAR/DLL 与固定启动绑定；同产品的多个构建、多个 Patch 配方分组匹配，缺件、混合集、重复身份、歧义及读取变化均不确认。
- Java J1 注册组件可与用户提供的未修改 YT00123 对照，结论限于组件；完整静态门槛证明单独报告“当前代码静态放行（Patch 来源待核）”。
- .NET 严格识别完整托管常量返回及本地引用置空短路形态，作为局部替换候选；不采用末尾返回值、方法名或网络字符串消失来确认 Patch，不覆盖复杂永久记录生成、保护器或 VM 的任意替换。
- GUI 新增“代码证据”列；JSON 保留代码行为、组件对照、授权入口与完整代码比对的独立证据。所有已确认组件证据与最终文件观测核对，变化即撤回。

用户已确认 DS0101、DS0105 目前没有使用方式三。两者的本地授权判据通过，应显示绿色授权入口通过；不能因此声称已经改写代码。当前仍没有来源可核验的同版原版/Patch 文件对，生产可信 Patch 指纹库未填入猜测或自制样本。

扫描严格只读，不执行目标注册组件、Patch 或授权写入。证据不足的网络、硬件狗、组合产品映射、受保护协议和运行缓存继续待核。
