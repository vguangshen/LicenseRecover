# LicenseRecover v1.2.7

本版本根据实际 QT40101 平台补齐 QT401 授权族识别，并加入“识别成功不等于可安全写入”的执行资格保护层。

## QT40101

实机样本显示：

- `systemConfig.yml`: `global.system.VersionID=QT40101`
- `WEB-INF/classes/config.xml`: `SoftVersionID=QT40101`
- `WEB-INF/classes/config1.xml`: `SoftVersionID=QT401`
- 应用授权初始化使用 `RegisterMain("QT401")`
- 配置中没有静态 `regInfo`；授权项由现有 `RegisterMain.getRegInfo().getRegStr()` 动态读取

因此 v1.2.7 显示：

- 类型/授权代际：`Java / QT401 / classes-config`
- SoftVersionID：`QT40101`
- 授权族：`QT401`
- 运行校验ID：`QT401`
- RegStr：`未静态声明`
- 状态：`待确认`

## 安全执行资格

- 对 Java classes-config，只有授权族、运行校验ID、RegStr 都有确认依据时，推荐一键恢复才可执行。
- QT40101 当前不会猜测 `RegStr=QT40101`，也不会再使用旧 44 项通用列表。
- 批量推荐操作自动跳过“待确认”项目；其它已确认平台继续正常执行。
- 核心 CLI 同样在 RegStr 未确认时于写文件前停止，避免绕过 GUI 误写。
- .NET Modern 产品号未确认时也会被批量推荐操作跳过。
- 方式三属于独立高级操作，仍按原有流程使用。

## 后续

如果将来能从 QT40101 的有效现有授权中可靠恢复原 RegStr，可以再增加“只复用已验证原授权项”的恢复路径；在此之前默认不写入最安全。
