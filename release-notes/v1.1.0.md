# LicenseRecover v1.1.0

This release adds the first built-in GitHub update path while keeping the existing Java 8 / Windows compatibility boundary.

## Highlights

- The default modern launcher now checks the latest stable GitHub Release in the background after startup.
- Update checks use GitHub's public `releases/latest` API and therefore require the repository to be public.
- When a newer stable version exists, the user can download and install it directly from the software.
- The updater downloads both `LicenseRecover-latest.zip` and `SHA256SUMS.txt` and refuses installation if SHA-256 validation fails.
- Installation runs from a temporary helper class outside the active overlay JAR so Windows can replace the running runtime files safely.
- Existing files that will be replaced are backed up to a temporary rollback directory before copying the new release.
- ZIP extraction rejects path-traversal / zip-slip entries.
- After a successful update, the updater restarts `run_gui.bat` automatically.
- `run_gui.bat --update-only` performs a manual update check without opening the main GUI.

## Update source

Stable updates are resolved from:

`https://api.github.com/repos/vguangshen/LicenseRecover/releases/latest`

Only versioned stable Releases (`vX.Y.Z`) are used for self-update. `rolling-latest` remains a prerelease and is intentionally ignored by the automatic updater.

## Compatibility

- Java 8 compatibility remains the baseline.
- Existing modern / legacy launchers remain available.
- The application can still start if the update check fails; automatic startup checks fail silently unless a user explicitly runs `--update-only`.

## Assets

- `LicenseRecover-latest.zip`
- `SHA256SUMS.txt`
