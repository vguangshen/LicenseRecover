# LicenseRecover v1.2.31

本版根据真实 Windows / .NET Framework 上 YX030101 的 v1.2.30 回归结果继续修复 ASP.NET host。

## 根因

v1.2.30 已经正确识别到小写 `itmcRegedit.dll` 并进入 `LicenseRecover.NET.AspNetHost.exe`，但 host 在设置经典 ASP.NET 的 `.appPath` / `.appVPath` 后又调用了五参数 `SimpleWorkerRequest(appVirtualDir, appPhysicalDir, ...)`。真实 .NET Framework 会把这视为“在已有应用上下文中再次覆盖应用路径”，因此在调用目标注册组件之前直接抛出 `System.Web.HttpException`：`SimpleWorkerRequest 构造函数的无效使用。无法在此上下文中重写应用程序路径。`

## 修复

- `CreateContext()` 保留目标站点物理根目录的 `.appPath` 与虚拟根 `/`。
- 改用不覆盖应用路径的三参数 `SimpleWorkerRequest("default.aspx", "", TextWriter.Null)`。
- 这样 `HttpContext.Current.Server.MapPath("~/Register.xml")` / `MapPath("~/config.xml")` 继续解析到目标站点根目录，同时避免真实 .NET Framework 的应用路径覆盖异常。
- 小写 `itmcRegedit.dll` 优先、大写 `ITMC.Regedit.dll` 回退、PRE-BLOCK FIRST、失败回滚、目标原生 `DoRegistry()` / `CheckReInfo()` 等策略全部保持不变。

## 验证重点

真实 YX030101 应不再停在 `ASPNET_HOST -> SimpleWorkerRequest` 构造阶段，而继续进入原 helper 的 `GENCODE`。如果目标注册组件内部仍有后续异常，现有结构化错误窗和持久日志会继续显示内层异常。
