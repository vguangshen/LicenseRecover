# LicenseRecover v1.2.34

本版继续修复真实 YX030101 小写 `itmcRegedit.dll` 注册链在 v1.2.33 中仍然出现 `TargetInvocationException` 的问题。

## 根因

v1.2.33 已经能从目标站点的 `bin\itmcRegedit.dll` 正确解析程序集，但 helper 仍运行在 LicenseRecover 工具自己的 AppDomain 中。脱壳后的目标注册组件显示：

- `RegeditMain` 构造函数直接使用 `AppDomain.CurrentDomain.BaseDirectory + "\\Register.xml"` / `"\\config.xml"`；
- `getRegNo()`、`CheckReInfo()`、`CheckLocalReg()` 等方法同时使用 `HttpContext.Current.Server.MapPath("~/...")`；
- 静态初始化还会从当前 AppDomain 的配置文件读取 `appSettings["Service"]`。

因此仅保留 `HttpContext` 和目标 `bin` 解析还不够：BaseDirectory 与 ConfigurationFile 仍指向 LicenseRecover 自身，目标组件并未真正运行在与 IIS 网站一致的应用环境中。

## 修复

- 为每次小写注册链创建独立的目标 AppDomain。
- `ApplicationBase` 指向目标网站根目录；`PrivateBinPath=bin`。
- 若存在目标 `web.config` / `Web.config`，将其设置为该 AppDomain 的 `ConfigurationFile`。
- 在目标 AppDomain 内重新创建 `HttpContext`，因此 `Server.MapPath("~/...")` 仍解析到真实站点根目录。
- 在目标 AppDomain 内预加载 `bin\itmcRegedit.dll`，并继续从同一目标 `bin` 解析依赖。
- 在该目标 AppDomain 内调用原 helper 的 `ParseArgs -> RunDirect`，不修改目标 DLL，也不改变申请号、离线授权码、`DoRegistry()`、`CheckReInfo()` 算法。

## 新诊断

日志会新增：

- `[ASPNET_HOST] appDomainBase=...`
- `[ASPNET_HOST] appDomainConfig=...`
- `[ASPNET_HOST] helperDispatch=RunDirect/target-AppDomain`

对于 YX030101，`appDomainBase` 应为网站根目录，`appDomainConfig` 应为该站点自己的 `web.config`。
