# LicenseRecover v1.2.69

## 实际识别授权条件，激活/Patch 统一绿色

- 新增独立状态“授权检查通过（激活或 Patch）”，有证据通过时统一绿色，默认不再勾选执行恢复。仍保留原生许可、可信 Patch 对照和独立接受条件的不同证据，不把未知变成绿色。
- .NET 采用已审核代码的独立只读正向谓词：网站/注册/密码与 JSON 等依赖指纹匹配、本地优先分派、载荷结构、当前机器绑定、日期、无限计次及当前产品模式必须同时通过。没有执行目标程序集、写注册文件或消耗次数。其他方式失败不能据此判未激活。
- Java DS2406 根据已审核的全部 329 个应用 class、145 个 JAR 与 9 个启动/Struts 配置，确认当前代码的授权门槛放行。没有加载目标类或修改程序；这不是来源可信的 Patch 版本认定。
- 授权状态与检测原因移动到“应用”之后，首屏可见；鼠标悬停查看完整证据。

## 当前样本结果及限制

同一台机器的 26 个独立扫描输入副本中，8 个满足本轮已审核的正向证明：DS2406、DS0101、DS0105、DS0107、DS0109、YX030308、YX030321、YX030322。其余 18 个保持未验证。检测实时读取当前文件和本机信息，其他机器、代码或配置可能有不同结果，不能按目录名套用上述状态。

绿色表示当前已审核的授权条件或门槛接受，不区分厂商激活与修改来源，不保证网站、数据库、日志系统等全部业务功能可运行。原生许可有效性仍未独立确认，真实原版/Patch 双指纹库仍为空。非空 WebSerSoftNo 覆盖号、有限计次与尚未闭合的网络/硬件狗路径保留未知。

请用“扫描子目录”验证状态和具体原因，无需执行一键恢复或方式三。已有版本可使用“检查更新”，完整包包含 Windows x64 Java 8 JRE；两份 ZIP 使用 SHA256SUMS.txt 校验。

## 审计过程事故披露

一个私有辅助审计脚本因变量覆盖，曾将审计 JSON 误写到真实 DS2406 的 WEB-INF/web.xml。该失误已向用户披露，并使用事先校验的原始副本恢复了原字节与原修改时间；恢复哈希与初始记录一致，重新核对的 11,458 个源输入未发现残留差异。出错脚本已禁用，后续辅助输出增加目录限制。不能称本轮审计过程始终只读；生产检测器没有这条写入路径。

检测证明与边界见 docs/DOTNET_READ_ONLY_ACCEPTANCE.md、docs/JAVA_STATIC_ACCEPTANCE_PROOF.md。
