# LicenseRecover v1.2.4

本版本集中修复软件自更新的网络可靠性与下载进度显示。

## 真实下载进度

- 更新器直接读取 GitHub Latest Release API 中每个发行资产的 `size`。
- `LicenseRecover-update.zip` / `LicenseRecover-latest.zip` 下载开始前即可得到总字节数。
- 进度条按“实际已写入临时文件的字节数 / Release 资产总字节数”计算 0%-100%，并显示已下载与总大小。
- 状态文字会随“连接下载节点 → 下载 → 自动重试 → SHA-256 校验”阶段同步变化。
- 即使 GitHub CDN 使用 chunked transfer 或没有返回 `Content-Length`，进度仍保持确定值。

## 网络可靠性

- 连接超时由 8 秒提高到 30 秒，读取超时由 30 秒提高到 60 秒。
- 单次下载最多自动尝试 4 次，并采用递增等待时间。
- 如果连接在下载中途断开，会保留已下载临时文件；下载节点支持 Range 时从断点继续。若节点忽略 Range，则安全地从 0 重新下载。
- 原生 `LicenseRecoverGUI.exe` 增加 `-Djava.net.useSystemProxies=true`，让内置 Java 8 使用 Windows 系统代理发现机制。
- 下载请求显式使用 `Accept-Encoding: identity`，避免压缩传输影响文件字节进度和 Range 语义。

## 完整性保护

- 若 GitHub Release API 给出了资产大小，下载结束后会先校验实际文件长度。
- 之后仍必须通过 `SHA256SUMS.txt` 中的 SHA-256；任何长度或哈希不一致都不会安装。
- ZIP 路径穿越防护、覆盖前备份、失败回滚和 EXE 直接重启逻辑保持不变。

## 从旧版升级说明

本修复代码只有在 v1.2.4 已经运行后才会生效。v1.2.2/v1.2.3 在下载 v1.2.4 的第一次升级过程中仍运行旧更新器；如果旧更新器在你的网络环境仍然出现 `connect timed out`，需要使用浏览器手动下载一次 v1.2.4 完整便携版。升级到 v1.2.4 后，后续在线更新将使用本版本的新连接、重试、系统代理与真实进度逻辑。
