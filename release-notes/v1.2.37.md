# LicenseRecover v1.2.37

本版针对真实 YX030101 小写 `itmcRegedit.dll` 链停止继续微调人工 `SimpleWorkerRequest`，改为先在 Windows/.NET Framework 上复现失败，再使用 .NET Framework 自己的 ASP.NET Hosting API 建立真实站点应用域。

## 已先复现的 v1.2.36 问题

在 Windows Server 2025 / .NET Framework 4.x 测试机上，v1.2.36 的旧宿主可以稳定复现与用户服务器相同的错误：

`System.Security.Permissions.FileIOPermission -> System.Web.InternalSecurityPermissions.PathDiscovery -> HttpRequest.MapPath -> HttpServerUtility.MapPath`

根因是手工创建的 AppDomain + `SimpleWorkerRequest` 并没有得到 ASP.NET 自己完整的 `HostingEnvironment` / 配置映射 / 文件权限上下文。

## v1.2.37 修复

- 使用 `System.Web.Hosting.ApplicationManager` 创建真实 ASP.NET application AppDomain，不再自行拼装 `.appDomain/.appPath/.appVPath`。
- 新增内部 `LicenseRecover.NET.AspNetBridge.dll`。Host 仅在调用期间把它暂存到目标 `bin`，让 ASP.NET 在目标站点 AppDomain 内加载；完成后关闭 Hosted AppDomain 并删除临时 Bridge。
- Hosted AppDomain 必须同时满足：
  - `HostingEnvironment.IsHosted = true`；
  - `HostingEnvironment.ApplicationPhysicalPath = 目标站点根目录`；
  - `HttpRuntime.AppDomainAppPath = 目标站点根目录`；
  - `~/Register.xml` 与 `~/config.xml` 精确映射到目标站点。
- 上述环境验证通过后，才预加载目标小写 `itmcRegedit.dll`，执行只读 `GetRegNo()` probe，再执行原 helper 的 `ParseArgs -> RunDirect`。
- 不修改目标 DLL，不改变目标组件的申请号、离线授权码、`DoRegistry()`、`CheckReInfo()` 算法；小写优先、大写回退策略保持不变。

## Windows 集成验证

发布前增加 Windows/.NET Framework 集成夹具，模拟真实 YX030101 的关键条件：.NET 4.5、`identity impersonate=true`、站点根 `Register.xml/config.xml`、目标 `bin/itmcRegedit.dll`、注册产品 `YX0302`。

集成测试必须实际看到并验证：

- `[ASPNET_HOST] hosted AppDomain created; appId=...`
- `[ASPNET_HOST] hostingEnvironment appVirtualPath=/ ...`
- `[ASPNET_HOST] mapPath Register.xml=...\YX030101\Register.xml`
- `[ASPNET_HOST] mapPath config.xml=...\YX030101\config.xml`
- `[ASPNET_HOST] target request-code probe=OK; hostIdLength=16`
- `[ASPNET_HOST] helperDispatch=RunDirect/hosted-AppDomain`

这条 Windows 集成链已经在测试分支上完整通过后，才进入正式 v1.2.37 发布流程。
