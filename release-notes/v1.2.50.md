# LicenseRecover v1.2.50

本版修复 BKSM4 在 LicenseRecover 中显示成功、但 Tomcat 使用真实启动注册链时仍失败的问题。

## 根因

目标 BKSM4 的 `Global.<clinit>` 中存在两条看似匹配的注册数据：

- 陈旧、未提交：`QT04 / QT0435 / BKSM4`；它只执行 setter，并没有加入 `registerProductBeans`。
- 真正生效：`PT02 / QT0445 / BKSM4`；目标字节码随后执行了 `registerProductBeans.add(bean)`。

旧解析器在看到 `setProductNums("BKSM4")` 后立即返回，因此误把第一条未提交 Bean 当成 Tomcat 运行时映射，造成生成的本地注册信息和目标启动链不一致。

## 修复

- 只有同一 `RegisterProductBean` 被实际提交到目标 `registerProductBeans` 后，映射才可用于自动恢复。
- 对真实 BKSM4，预期计划为：

```text
SoftVersionID=BKSM4
AuthorizationFamily=PT02
RuntimeProductID=PT02
RegStr=QT0445
automaticRecoveryReady=true
```

- 不通过内置产品表硬编码 BKSM4 -> PT02；目标自身 `Global.class` 仍是唯一权威映射证据。
- 匹配 Bean 未执行 `registerProductBeans.add(...)` 时继续 fail-closed。

## 验证

真实 BKSM4 样本已用于本地映射/计划验证；完整 Java 8 CI 同时覆盖 BKSM4 正反回归，以及既有 DS50109、YX030506 和其他 Java/.NET 回归后再生成正式发行包。
