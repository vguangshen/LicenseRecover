# LicenseRecover v1.2.59 — DS0101 native offline recovery test candidate

**Release candidate / testing only.** This version has not been proven on a deployed production IIS site after an application-pool restart. Test against a complete backup of a site you are entitled to maintain. The stable v1.2.58 release remains available.

## RC4 — DS01xx family recognition and shared .NET recovery (2026-10-28)

- **Experimental DS01xx family detection:** for DS0107 and related `DS01xx` configurations, determine the current SoftVersionID and `itmcIEC` product from each site's own files, instead of demanding the known DS0101 SHA-256 pair.
- **Fail-closed native ABI gate:** before reading or modifying registration data, a Windows `ReflectionOnlyLoadFrom` probe verifies the original `RegeditMain` constructor, `NewRegistry`, `DoRegistry`, `CheckLocalReg`, `CheckReInfo`, `RegeditInfo` fields and website `CheckReg` signature.
- Both single-application and batch modes use the existing shared native registration runner, verified backups, preview rollback, network isolation, and post-write website verification. A differing version ID is passed into both code generation and native verification; a DS0101 local record cannot validate DS0107.
- Updated UI labels show an old-protocol family candidate and pending ABI validation rather than always claiming unsupported.
- Synthetic Windows tests cover DS0107 cross-version rejection and the common ABI. The **real DS0101 DLLs** were re-tested through the updated Java one-click coordinator on a disposable private Windows Runner copy (one-click reported success; original sample unchanged).
- **Important limitation:** no real DS0107 commercial DLL or complete DS0107 IIS application has been tested. Method signatures and filename/version matching do not prove identical product-specific licensing behavior. Test this RC on an isolated DS0107 copy with complete backups; never assume a successful generic family match means activation.
- Existing stable v1.2.58 and RC3 remain available. RC4 is a prerelease, not a production-stable release.

## RC3 — Fix Java `NoSuchMethodError` in downloaded release (2026-10-28)

- Fixed packaging mismatch in RC2: `LicenseRecoverModernGUIAutoRecovery` called the new `LegacyDotNetProtocol.generateAuthorizationCode(String, String, String): CodeResult`, while the runtime overlay omitted `LegacyDotNetProtocol.class` and its nested classes.
- Add `LegacyDotNetProtocol.class`, `LegacyDotNetProtocol$CodeResult.class`, `$SequenceInfo.class`, and `$AuthorizationInfo.class` to the same runtime JAR as the compiled coordinator.
- CI now loads the runtime-JAR-first GUI classpath, checks that the protocol and coordinator resolve from the same runtime JAR, and confirms the **exact JVM method descriptor**, including the `CodeResult` return type. This regression test is independent of the source-classes test.
- The crash was in the LicenseRecover launcher/runtime distribution, **not** a DS0101 native registration rejection. The previous run had reached native request generation, but had not submitted the authorization writeback.
- Use a **fresh directory** to test RC3. Extracting on top of RC2 can leave older JARs or running processes in place. Keep the original IIS website backup.
- RC2 progress, finite firewall-command timeout and responsive UI changes remain included.

## RC2 — One-click freeze / blank-log fix (2026-10-28)

- Fixed Windows Firewall `netsh` setup and cleanup commands that could wait without a deadline. They now use a bounded, terminate-on-timeout process runner (20 seconds per OS command), with an explicit pre-block failure instead of indefinite UI waiting.
- Moved persistent one-click logfile writes off the Swing event-dispatch thread. The visible log renders immediately and still works if the persistent logger is slow or unavailable.
- The one-click status now names the current phase (snapshot, firewall isolation, native request generation, registration write, verification, rollback) and displays elapsed seconds.
- Java source smoke tests cover the new bounded firewall call and stage-label behavior; the exact RC2 commit must pass both Windows .NET integration suites and full Verify source CI before GitHub publishes it.
- Previous RC1 local Windows user feedback: the GUI remained at `执行并校验中...` with an empty visible log. The fix addresses known unbounded waits and opaque progress; it does not prove which OS operation caused that specific stall. If the new version reports a timeout or pre-block error, preserve the non-sensitive stage log for follow-up.

## DS0101

- Enables an experimental DS0101 one-click and recommended batch path **only for the exact original analyzed ITMC.Regedit.dll + itmcRegedit.dll hashes**. Other DS01xx remain safely unsupported.
- Reuses the same Windows ASP.NET native host, temporary network guard, native request/writeback stages, verified registration backups, rollback and batch execution as the supported .NET families.
- Derives machine-bound DS0101 old-format offline authorization data from the site's own NewRegistry request and submits it through the original DoRegistry method.
- Interprets the vendor's distinct success/error-flag conventions: CheckLocalReg must confirm matching DS0101, itmcIEC and nonexpired registration; original CheckReInfo and Web.CheckReg must both report no registration error.
- Rechecks original website registration on the final configuration, refuses false success and restores the original registration files if any stage fails.

## Test evidence

- Open-source Java/Mono CI and both synthetic Windows .NET Framework ASP.NET-host integration suites passed.
- Private Windows testing on the user's original DS0101 binaries validated the offline request, native writeback, local record and original website verification.
- A separate private Windows test invoked the actual Java one-click coordinator on a disposable copy of the **original protected DLLs**: original sample hashes matched, the native one-click returned success, the source sample remained unchanged.
- No original proprietary binaries, site configuration, machine IDs or authorization codes are included in this release.

## Before deploying on local IIS

1. Back up the **entire** original website (not just config.xml), stop its IIS app pool and test on a copy where possible.
2. Use the recommended one-click action on DS0101, or preview/batch to review eligibility. Unsupported DLL versions will be rejected rather than guessed.
3. Restart the IIS app pool/site and independently verify that authenticated login and registered features function after the restart.
4. If the native checks fail, do not interpret the helper's local writeback as successful activation. Preserve logs and use the generated preoneclick backups if recovery is needed.

**Not covered:** full production web.config, database initialization, persistent entitlement after real IIS recycle, or deployments with different original DS0101 DLL hashes. These require the user's local test and must not be inferred from GitHub Runner success.
